概念

Web 服务器（WWW）是什么

定义

  • Web 服务器又称 WWW（World Wide Web）服务器
  • 本质是一个向浏览器提供文档的程序
  • 浏览器发出请求，服务器把网页文档回送给它

作用

  • 主要提供网上信息浏览服务
  • WWW 是 Internet 上使用最广、发展最快的服务之一
  • IIS 就是 Windows 上的一种 Web 服务器实现
联系本课：今天在同一台 IIS 上跑多个站点，就是让一个 Web 服务器"同时提供多份文档"。
这页补充教材的必备知识。Web 服务器也叫 WWW 服务器，WWW 是 World Wide Web 万维网的缩写。说得通俗一点，Web 服务器就是一个"向发出请求的浏览器提供文档的程序"：你在浏览器里敲网址回车，就是向 Web 服务器发请求，服务器把对应的网页文档回送给浏览器显示出来。它的主要功能就是提供网上信息浏览服务，WWW 也是 Internet 上发展最快、用得最广的服务，正是因为有了它互联网才迅速普及。我们学的 IIS 就是 Windows 平台上的一种 Web 服务器。理解了这个，今天"在一台 IIS 上建多个站点"就好懂了——无非是让这个程序同时对外提供好几份不同的文档。

概念 1

绑定：IIS 靠三要素认网站

IP 地址10.10.10.10 或 *
+
端口80 / 8080
+
主机名www / hr.lab.local
=
唯一的站点三者组合不能重复
方式区分依据本课例子
主机头同 IP 同端口，不同域名www / hr.lab.local :80
端口同 IP，不同端口DevSite :8080
IP服务器有多个 IP本课不做（只有一个 IP）
第 9 课 CompanySite 绑定的是 *:80 且主机名为空，它是 80 端口的"兜底"站点。IIS 优先匹配带主机名的绑定，匹配不上的请求才交给主机名为空的站点。提问：如果两个站点都绑 *:80 且主机名为空，会怎样？（第二个站点无法启动，提示绑定冲突）
概念 2

主机头：同一个 IP，怎么分出两个站？

CLIENT1 访问 http://hr.lab.local 时：

① 问 DNShr.lab.local
→ 10.10.10.10
→
② 连接10.10.10.10:80
→
③ 请求头Host: hr.lab.local
→
④ IIS 匹配交给 HRPortal
DNS 负责"去哪台服务器"——两个名字指向同一个 IP
Host 头负责"要哪个网站"——IIS 按名字分发
用 IP 访问时 Host 头是 IP，只有主机名为空的绑定能接住这个请求。
这页是本课排障的核心。DNS 和绑定缺一不可：DNS 错了浏览器连不到服务器；绑定错了能连上，但打开的是别的站。可以让学生在浏览器 F12 网络面板里亲眼看到请求头中的 Host 字段。
概念 3

虚拟目录：URL 路径 ≠ 磁盘路径

站点 CompanySite · C:\WebSites\CompanySite
📄 /index.html📁 /docs（子文件夹）
虚拟目录 /shared
📁 → C:\SharedDocs
类型特点
子文件夹就在站点目录里，自动可访问
虚拟目录别名映射到站点外的任意路径
应用程序虚拟目录 + 独立应用程序池，可单独运行代码
用途：不复制文件，就能把共享资料、上传目录挂进网站。
访问 /shared/shared.txt 时，IIS 把别名 shared 换成 C:\SharedDocs，再读取 shared.txt。应用程序与虚拟目录的区别：应用程序有自己的应用程序池和 web.config 作用域，常用于在同一站点下部署独立的 ASP.NET 程序；本课实操只做虚拟目录。
任务 1 · 24′ · DC1

准备 HRPortal 内容和 DNS 记录

① 创建第二个网站的目录和首页

mkdir C:\WebSites\HRPortal
@"
<html><body><h1>HR Portal</h1>
<p>Human Resources Internal Site</p></body></html>
"@ | Out-File C:\WebSites\HRPortal\index.html `
  -Encoding UTF8
② 在 lab.local 区域添加两条 A 记录

Add-DnsServerResourceRecordA -ZoneName "lab.local" `
  -Name "www" -IPv4Address "10.10.10.10"
Add-DnsServerResourceRecordA -ZoneName "lab.local" `
  -Name "hr" -IPv4Address "10.10.10.10"
@" 和 "@ 必须各自独占一行、顶格写，否则 here-string 报错。两条 A 记录指向同一个 IP，这正是概念 2 的前提。若提示记录已存在，说明之前做过，可直接继续；可用 Resolve-DnsName hr.lab.local 立即验证。

添加 HRPortal，并给 CompanySite 加主机名

在 CLIENT1 上按名字访问

在 CLIENT1（VM3）上，先确认 DNS 指向 10.10.10.10

任务 2 · 12′ · DC1

基于端口的第三个站点 DevSite


mkdir C:\WebSites\DevSite
"<html><body><h1>Dev Environment</h1></body></html>" |
  Out-File C:\WebSites\DevSite\index.html -Encoding UTF8
网站›添加网站›名称 DevSite · 端口 8080 · 主机名留空

New-NetFirewallRule -DisplayName "Allow HTTP 8080" `
  -Direction Inbound -Protocol TCP `
  -LocalPort 8080 -Action Allow
测试：CLIENT1 浏览器访问 http://10.10.10.10:8080 → "Dev Environment"
IIS 安装时只自动放行 80/443，自定义端口必须手动开防火墙，否则本机 localhost:8080 能打开、CLIENT1 打不开——这是本任务最典型的现象。提问：端口方式和主机头方式各有什么缺点？（端口方式要记端口号、要开防火墙；主机头方式依赖 DNS）

排障

站点打不开？按这个顺序查

现象原因处理
浏览器"找不到服务器"CLIENT1 解析不到名字DNS 指向 10.10.10.10，ipconfig /flushdns
hr.lab.local 打开的是公司首页HRPortal 主机名没填对检查绑定是否为 hr.lab.local
站点启动失败，提示端口被占用两个站点同为 *:80 且无主机名先给 CompanySite 加主机名
本机 8080 能开，CLIENT1 不能防火墙没放行检查 "Allow HTTP 8080" 规则

为什么

怎么做
