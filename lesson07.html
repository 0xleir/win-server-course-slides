概念

协议、安全弱点与两种共享模型

FTP · 文件传输协议

  • 工作在应用层（OSI 第 7 层 / TCP 第 4 层）
  • 基于 TCP 而非 UDP，面向连接
  • 传输前先完成三次握手，连接可靠

SMB · 局域网文件共享

  • Server Message Block，本课共享走的就是它（445）
  • 靠客户端发送验证密码来授权文件传输
  • 弱点：密码可被截获 → 窃取访问权限
组策略「本地账户的共享和安全模型」经典（Classic）仅来宾（Guest only）
身份处理验证本地用户，保留本来身份验证本地用户，但身份降为来宾
网络登录需输入用户名 + 口令只需 guest 口令，无口令直接进
安全性可精细授权，推荐难以追溯，风险高
加固方向：服务器共享选"经典"模型，让网络访问必须带账号口令，才能发挥第 6 课按部门分配的 NTFS 权限。
这页把教材 P3 的三块必备知识压到一张卡上。第一块是 FTP：文件传输协议工作在 OSI 第七层、TCP 模型第四层也就是应用层，用的是 TCP 不是 UDP，客户端和服务器建连前要经过三次握手，保证连接可靠、面向连接，为数据传输提供可靠保证——这是"文件怎么在网络上传"的通用底层，和本课的 SMB 共享并列理解即可。第二块是 SMB：Server Message Block 是局域网文件共享传输协议，本课客户端访问共享走的 445 端口就是它。它控制文件安全传输的机制是客户身份验证——客户端向服务器发送验证密码换取传输权限；弱点在于针对该机制的网络攻击较严重，攻击程序可以截获验证密码来窃取文件访问权限，局域网下传输安全得不到充分保障，这也是后面安全配置课要加固的原因。第三块最关键，用右边表格对比：组策略里"网络访问:本地账户的共享和安全模型"有两种，经典模型对本地用户做身份验证且不改变其本来身份，网络登录共享服务器时必须输入用户名和口令；仅来宾模型同样做验证但把身份统一降为来宾，登录时不需要用户名，只要输入 guest 账户口令，如果 guest 没设口令就直接登录。显然经典模型安全得多——它让我们第 6 课按部门配的 NTFS 权限真正能区分出"谁是谁"，所以服务器共享加固时要选经典、关掉来宾模型。

概念 2

网络访问要过两道门

网络用户bob
→
第 1 道：共享权限完全控制 / 更改 / 读取
→
第 2 道：NTFS 权限第 6 课配置的 ACL
→
文件readme.txt

有效权限 = 取交集

两道门都允许的操作才能做，以更严格的为准。例：更改 ∩ 修改 = 修改

拒绝优先

任一道门是"无访问/拒绝"，直接被挡，根本不看另一道

本地登录只过 NTFS 一道门；网络访问两道都要过。
这页是本课核心。可以比喻：共享权限是大楼门禁，NTFS 是办公室门锁。企业常见做法是共享权限放宽（如 Everyone 更改），用 NTFS 精细控制，这样只需维护一套规则。提问：bob 本地登录 DC1 时，共享权限还起作用吗？
概念 3

ABE：看不到，就不会去点

未启用 ABE（默认）

  • 打开共享，所有子文件夹都列出来
  • bob 也能看到 Confidential
  • 点进去才提示"拒绝访问"
  • 暴露了目录结构，还引发求助电话

启用 ABE（AccessBased）

  • 只列出用户有权访问的项目
  • bob 看不到 Confidential
  • alice 照常可见
  • 不改变权限，只改变"显示"
ABE = Access-Based Enumeration，基于访问的枚举。它是共享的属性，只对网络访问生效。
第 6 课中 Confidential 只保留了 Administrators 和 alice，正好用来演示 ABE。强调 ABE 不是权限：即使看不到，权限依然由 NTFS 决定。它和隐藏共享一样属于"减少暴露"，不能替代权限配置。
任务 1 · 19′ · DC1

图形界面创建隐藏共享 Public$

右键 C:\CompanyData\Public›属性›共享›高级共享

① 勾选

共享此文件夹

② 共享名

Public$

③ 权限

Everyone → 更改
为什么 Everyone 可以给"更改"？第 6 课已用 NTFS 给 Public 设了权限，真正的控制在第二道门。
注意要点"高级共享"，不要用上面的"共享"按钮，那个是简易向导，共享名不能自定义。默认的共享权限是 Everyone 读取，需要点"权限"按钮改成更改。$ 必须是共享名最后一个字符。
任务 1 · 19′ · DC1

PowerShell 创建部门共享


New-SmbShare -Name "IT-Share" -Path "C:\CompanyData\IT" `
  -FullAccess "IT-Admins" -ChangeAccess "IT-Users" `
  -ReadAccess "Everyone"
New-SmbShare -Name "Finance-Share" `
  -Path "C:\CompanyData\Finance" -FullAccess "IT-Admins" `
  -ChangeAccess "Finance" -NoAccess "IT-Users"
查看所有共享（两种方式结果应一致）

Get-SmbShare | Format-Table Name, Path, Description
net share
-NoAccess "IT-Users" 是本课的伏笔：charlie 同时属于 IT-Users 和 Finance，任务 2 中他访问 Finance-Share 的结果值得课堂讨论。net share 中会看到 C$、ADMIN$、IPC$ 等默认共享，以及刚建的 Public$。

排障

访问不了共享？按这个顺序查

现象原因处理
找不到网络路径网络不通或防火墙拦 445先 ping 10.10.10.10，再查 DC1 防火墙的"文件和打印机共享"
换了用户还是旧身份会话被缓存net use * /delete 后重新连接
发生系统错误 85盘符已被占用先 net use S: /delete
能看见但改不了两道门取交集分别查共享权限和 NTFS 权限
系统错误 1219 多重连接同一服务器已用别的用户连接断开旧连接后再映射
课堂上最常见的是第二种：学生换用户测试却得到同样结果，误以为权限没生效。错误 1219：同一服务器不能用两个不同用户同时连接，alice 映射 S: 后再用 charlie 映射 F: 就可能触发，可先断开或用 \\DC1 与 \\10.10.10.10 两种名称区分。浏览看不到 Public$ 是隐藏共享的正常现象。

本课小结

为什么

共享让文件通过 SMB 被网络访问，ABE 和隐藏共享减少暴露

怎么做

New-SmbShare → UNC 访问 → net use 映射 → Set-SmbShare

关键点

网络访问过两道门：共享 ∩ NTFS，拒绝优先
