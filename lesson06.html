NTFS 权限管理

决定"谁能读、谁能改、谁根本看不到"

概念

文件共享：两套权限各管一段

共享文件夹的四件事

  • 建立共享文件夹，供网络访问
  • 设置文件夹共享权限（网络这道门）
  • 设置文件夹 NTFS 权限（磁盘这道门）
  • 添加共享用户账号，按部门分配

本课聚焦 NTFS 权限

  • NTFS 权限随文件走，本地与网络访问都生效
  • 按"所有权/只读/拒绝"给各部门分别授权
  • 共享权限留到第 7 课，与 NTFS 叠加取最严
权限体系作用范围由谁决定
NTFS 权限本地登录 + 网络访问都生效文件系统（本课）
共享权限仅网络访问经过共享点时共享设置（第 7 课）
原则：公司内部共享按部门建文件夹，本部门有读写删除复制等所有权，对其他部门只读或拒绝。
这一页承接教材"Windows服务器共享的搭建"任务分析。教材把文件共享拆成四个动作：建立共享文件夹、设置文件夹共享权限、设置文件夹 NTFS 权限、添加共享用户账号。要让学生明白：一个文件被网络用户访问时，要穿过"共享权限"和"NTFS 权限"两道门，两者取交集中最严格的那个才是最终能做的事。NTFS 权限随文件保存在磁盘上，不管本地登录还是网络访问都生效，所以是基础，本课先把它配透；共享权限只在从网络经过共享点时才叠加进来，留到第 7 课讲。教材给的业务场景是：公司按部门建文件夹，本部门人员对自己部门文件夹有读写删除复制等完整权限（可按用户细分），对其他部门文件夹按需只读或拒绝——这正是本课任务 2 要实现的部门隔离。

概念 1

NTFS 标准权限：一级包含一级

读取 R看内容、看属性
→
读取和执行 RX+ 运行程序
+ 遍历文件夹
→
修改 M+ 写入
+ 删除
→
完全控制 F+ 改权限
+ 取得所有权

常见误区

  • 给普通员工"完全控制"图省事
  • 员工就能自己改权限、把别人踢出去

正确做法

  • 最小权限：日常办公给"修改"就够
  • "完全控制"只给管理员组
修改和完全控制只差两项：更改权限、取得所有权，但正是这两项决定了谁是"管理者"。另有一个独立的"写入 W"权限，只能新建和写入、不能删除。提问：修改权限包含读取吗？（包含，任务 4 会验证。）
概念 2

权限继承：父文件夹往下传

C:\CompanyData（显式设置）
IT（禁用继承，重新设置）
📄 readme.txt
Confidential（再次禁用）
🔒 secret.txt
禁用继承时的选择结果
转换为显式权限把继承来的条目复制一份，之后可以逐条删改
删除所有继承的权限清空，只剩手动添加的条目（容易把自己锁在外面）
本课统一选"转换为显式权限"，再删除不需要的组。
默认情况下新文件夹会继承 C:\ 的权限，其中有 Users 组的读取，所以任何本地用户都能看到。灰色的复选框就是继承来的条目，不能直接删，必须先禁用继承。常见错误：选了"删除所有继承的权限"，结果连 Administrators 都没了。
概念 3

有效权限怎么算

① 累加

用户 + 所属各组的"允许"取并集

② 拒绝优先

显式"拒绝"压过"允许"

③ 没写 = 没有

ACL 里不出现，就访问不了

用户IT 文件夹Finance 文件夹Confidential
alice（IT-Admins）完全控制完全控制完全控制
bob（IT-Users）修改无无
charlie（IT-Users + Finance）修改修改无
这张表就是任务 2 配完后应该得到的结果，可以先让学生自己推算再揭晓。charlie 是累加规则的典型：两个组的权限合在一起。Confidential 只有 Administrators 和 alice，所以 bob、charlie 都进不去——这属于"没写就没有"，不是"拒绝"。

任务 2 · 24′ · DC1

图形界面：先禁用继承

右键文件夹›属性›安全›高级›禁用继承›转换为显式权限

2.1 根目录 C:\CompanyData：取消继承 → 转换为显式 → 删除 Users，再添加三个部门组。

任务 3 · 20′ · DC1

icacls：查看权限、读懂缩写

3.1 查看权限

icacls C:\CompanyData
icacls C:\CompanyData\IT
icacls C:\CompanyData\Finance
icacls C:\CompanyData\IT\Confidential
缩写含义
F / M完全控制 / 修改
RX读取和执行
R / W读取 / 写入
(OI)对象继承：传给文件
(CI)容器继承：传给子文件夹
对照任务 2 的设计表核对 icacls 输出，这是检查图形界面操作是否正确的最快方法。输出中带 (I) 的条目表示继承来的；禁用继承后应该看不到 (I)。提问：一个条目只有 (CI) 没有 (OI)，文件会得到这个权限吗？
任务 3 · 20′ · DC1

icacls：授予、备份、恢复

3.2 设置 Public 文件夹权限

icacls C:\CompanyData\Public /grant Everyone:(OI)(CI)M
icacls C:\CompanyData\Public /grant "IT-Admins":(OI)(CI)F
3.4 备份和恢复权限

icacls C:\CompanyData /save C:\LabFiles\acl_backup.txt /T
icacls C:\ /restore C:\LabFiles\acl_backup.txt
/T 递归处理所有子目录和文件；备份前确认 C:\LabFiles 已存在。恢复要在父目录 C:\ 上执行：备份里记的是相对路径 CompanyData\...。
(OI)(CI)M 的意思是"修改权限，同时传给子文件和子文件夹"。在 PowerShell 里括号可能被解析，若报错可以给整个参数加引号，如 "Everyone:(OI)(CI)M"。注意：/save 记录的是相对于父目录的路径（CompanyData\...），所以 /restore 必须在 C:\ 上执行；在 C:\CompanyData 上执行会报"找不到文件"（真机实测：处理 1 个文件时失败）。

排障

权限不符合预期？按这个顺序查

现象原因处理
删除 Users 时提示"继承"继承未禁用高级 → 禁用继承 → 转换为显式
bob 能读 Finance2.3 漏删 IT-Users 或仍有 Usersicacls 查看后删掉多余条目

改了组成员仍无效令牌在登录时生成关闭 runas 窗口重新打开

本课小结

为什么

NTFS 权限按用户和组控制文件访问，实现部门隔离与最小权限

怎么做

禁用继承 → 转换为显式 → 删改组；icacls 查看、授予、备份

关键点

权限累加、拒绝优先、没写就没有；用 runas 实测有效权限
