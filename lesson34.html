一句话：没有一层是万无一失的；防住的靠前三层，没防住的靠"看得见"。
举例：攻击者绕过防火墙（例如通过钓鱼进到 CLIENT1），USB 禁用和应用控制让他带不进、跑不了工具；即使都失败，Sysmon 的进程创建事件也会被转发到 DC1 留下证据。提问：如果只能做一层，你选哪层？引出下一页的优先级。可以把这张图画进你的加固记录。
概念 2

加固优先级：先做什么

顺序加固项理由
1备份 + 防火墙暴露面最大、见效最快；先备份才能放心改
2审计与 Sysmon先"看得见"，后面每一步出问题都有记录可查
3GPO 加固影响所有域成员，改前要想清楚链接到哪个 OU
4基线报告 + 扫描用证据收尾：报告 + nmap 对比
原则：每改一项，立刻从 CLIENT1 测一次业务；不要攒到最后一起测。
原文按"防火墙 → 组策略 → 审计 → 基线"排列，本页是本稿建议的思考顺序，课堂上仍按原文任务编号推进，但审计（任务 3）可以和任务 2 并行由不同角色完成。最常见的错误是一口气改完所有东西再测，结果网站打不开却不知道是哪一步造成的。
任务 1 · 22′ · DC1 + SVR2回顾第 16、21 课

防火墙统一策略

两台服务器都执行：默认阻止入站

Set-NetFirewallProfile -Profile Domain,Public,Private `
  -DefaultInboundAction Block -DefaultOutboundAction Allow
$in = @{Direction="Inbound"; Action="Allow"}
再分别放行清单端口（先在 DC1 上做，再在 SVR2 上做）

# DC1：DNS · DHCP · AD · HTTPS · WinRM
New-NetFirewallRule @in -DisplayName "DC1-TCP" `
  -Protocol TCP -LocalPort 53,88,389,445,636,443,3390,5985,5986
New-NetFirewallRule @in -DisplayName "DC1-UDP" `
  -Protocol UDP -LocalPort 53,67,68,88,389
# SVR2：HTTP·HTTPS·FTP·SMB·管理
New-NetFirewallRule @in -DisplayName "SVR2-TCP" `
  -Protocol TCP -LocalPort 21,80,443,445,3389,5985,5986,"50000-50100"
动手前先用第 16 课的 netsh advfirewall export C:\LabFiles\firewall-backup.wfw 备份。规则名 DC1-TCP 等是本稿命名；端口按原文，TCP/UDP 拆分是补充（DNS、Kerberos 两种都用，DHCP 只有 UDP，域控定位还用 UDP 389）。关键一步：默认阻止不会关掉以前课程建的 Any 来源放行规则（Allow-IIS、Allow HTTP 8080、Allow ICMPv4、Allow FTP、SMB-IT-Only 等），要真正"仅开放"必须把它们逐条禁用：Get-NetFirewallRule -Enabled True -Direction Inbound -Action Allow 审查后 Disable-NetFirewallRule。白名单里 DC1 的 445 给 SYSVOL（客户端拉 GPO）、5985/5986 给 WinRM 管理与日志转发、3390 给 RDP（第 21 课改过的端口），漏了会断掉任务 2/3；SVR2 的 50000-50100 是第 12 课固定的 FTP 被动端口。

第四步 · CLIENT1 上验证（第 19 课）

gpupdate /force
gpresult /r
本课取定：GPO 名 Hardening-Policy，链接到域根并用安全筛选只应用到 CLIENT1（计算机对象在 CN=Computers，链到 Company 管不到）。用 SRP 不用 AppLocker。
关键坑一：计算机配置只对计算机对象所在位置生效，CLIENT1 在 CN=Computers 容器，链到 Company OU 管不到它——所以把 Hardening-Policy 链接到域根，再用安全筛选（GPO 委派里 GpoApply 只给 CLIENT1）避免波及服务器。关键坑二：SRP 不要用"默认不允许 + 白名单路径"，那会把用户开始菜单快捷方式、AppData 下的程序全拦住（实测普通用户点 PowerShell 没反应），而且会让 PowerShell 进入 ConstrainedLanguage；本课改成"默认不受限 + 单条不允许规则 C:\LabFiles\*"，只封一个隔离目录，既能演示拦截又不影响日常使用。验证要用普通用户：管理员默认不完全受 SRP 约束。AppLocker 依赖 AppIDSvc 且版本限制多，课堂统一用 SRP。gpresult /r 里应出现 Hardening-Policy。
任务 3 · 18′ · DC1 + SVR2回顾第 4、24、29 课

审计全面启用

① 两台服务器都部署 Sysmon（第 29 课）

$cfg = "C:\Tools\sysmon-config.xml"
C:\Tools\Sysinternals\Sysmon64.exe -accepteula -i $cfg
Get-Service Sysmon64

② DC1 当收集器


wecutil qc
wecutil cs C:\LabFiles\subscription.xml

③ SVR2 当日志源（指向 DC1）


winrm quickconfig
# 注册表 ...EventForwarding\SubscriptionManager
# 值 1 = Server=http://DC-01.lab.local:5985
#        /wsman/SubscriptionManager/WEC,Refresh=60
Restart-Service WinRM
第 24 课的 auditpol 增强审计和第 4 课的审计策略应已在位，先用 auditpol /get /subcategory:"{0CCE9215-69AE-11D9-BED3-505054503030}"（登录子类别；中文系统写英文名 Logon 会报 0x57）确认，不用重做。本课用"源推送式"日志转发（实测最稳）：DC1 用 wecutil qc 当收集器、wecutil cs 建订阅 LabForward（订阅 XML 见详细步骤，必须含 Uri 元素和允许域计算机的 SDDL，订阅内容收集 SVR2 的 4624/4625/4672 和 Sysmon 日志）；SVR2 设 SubscriptionManager 注册表指向 DC1:5985 后重启 WinRM，1–2 分钟后 DC1 的"转发的事件"里就会出现 SVR2 的记录。SVR2 的 C:\Tools 下要有 Sysmon 文件，没有就从 DC1 用 445 拷过来。检查点：DC1 事件查看器 › Windows 日志 › 转发的事件 里出现来自 SVR2 的事件。
