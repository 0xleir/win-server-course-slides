概念 1

FTP 有两条连接

① 控制通道客户端 → 21 端口
登录、发命令
→
② 客户端发 PASV"给我一个数据端口"
→
③ 服务器回应端口号
如 50023
→
④ 数据通道传文件、列目录
模式数据连接由谁发起防火墙影响
主动 PORT服务器连回客户端客户端防火墙/NAT 常拦截
被动 PASV客户端连服务器的高位端口服务器要放行一段端口范围
这页是任务 1.4 和任务 3.2 的原理：只开 21 端口时，能登录但 ls 会卡住，因为数据通道被拦了。提问：为什么任务 1 先放行 49152-65535，任务 3 又缩小到 50000-50100？答：端口开得越少，攻击面越小。
概念 2

用户隔离：登录后被"关"在自己的目录

站点根 C:\FTPRoot
LocalUser（本地账户固定目录名）
alice
📄 readme.txt
bob
📄 readme.txt
登录用户看到的 "/"
aliceC:\FTPRoot\LocalUser\alice
bobC:\FTPRoot\LocalUser\bob
无对应目录登录被拒绝
LocalUser 这个名字是 IIS 规定的，拼错就隔离失败。
IIS 的规则：本地账户映射到 LocalUser\用户名，域账户映射到 域名\用户名（第 17 课之后才有域）。"禁用全局虚拟目录"意味着用户看不到站点级虚拟目录，彻底只剩自己的家目录。可以问学生：不隔离时 alice 能看到 bob 的文件吗？
概念 3

为什么要 FTPS

普通 FTP（任务 1–2）

  • USER / PASS 命令明文发送
  • 同网段抓包可直接看到 Lab@2026a
  • 文件内容也是明文

FTPS（任务 3）

  • 用 TLS 加密控制和数据通道
  • 复用第 11 课的 Lab SSL Cert
  • "需要 SSL"后拒绝明文登录
注意区分：FTPS = FTP + SSL/TLS（IIS 支持）；SFTP 是 SSH 的文件传输，和 IIS 无关。
第 26 课会用 Wireshark 抓包，这里先口头说明风险即可。很多学生会把 FTPS 和 SFTP 混为一谈，要点明：IIS FTP 只支持 FTPS，SFTP 需要 OpenSSH 服务器。
任务 1 · 20′ · DC1

安装 FTP 服务并准备目录

在 DC1 上，以管理员身份运行 PowerShell

Install-WindowsFeature Web-Ftp-Server -IncludeAllSubFeature
mkdir C:\FTPRoot
mkdir C:\FTPRoot\LocalUser\alice
mkdir C:\FTPRoot\LocalUser\bob
"Alice's file" | Out-File `
  C:\FTPRoot\LocalUser\alice\readme.txt
"Bob's file" | Out-File C:\FTPRoot\LocalUser\bob\readme.txt
目录结构现在就按隔离规则建好（概念 2），任务 2 只需打开开关。
-IncludeAllSubFeature 会同时装上 FTP 扩展性组件。装完后在 IIS 管理器里网站右键会出现"添加 FTP 站点"。如果 IIS 管理器已打开，需要关掉重开才能看到新菜单。
任务 1 · 20′ · DC1

创建 FTP 站点 LabFTP

IIS 管理器›网站›右键›添加 FTP 站点
向导页本课取值
站点信息名称 LabFTP，路径 C:\FTPRoot
绑定和 SSLIP = 全部未分配（*），端口 21，SSL 选"无"
身份验证勾选"基本"
授权指定用户 alice, bob，权限：读取 + 写入
先不开 SSL：先确认基础功能可用，任务 3 再加密，便于分步排错。
"基本"身份验证就是用户名密码登录，这正是明文风险的来源，呼应概念 3。授权里多个用户用英文逗号分隔。不要勾"匿名"，否则任何人都能连上。
任务 1 · 20′ · DC1

放行控制端口和被动端口


New-NetFirewallRule -DisplayName "Allow FTP" `
  -Direction Inbound -Protocol TCP `
  -LocalPort 21 -Action Allow
New-NetFirewallRule -DisplayName "Allow FTP Passive" `
  -Direction Inbound -Protocol TCP `
  -LocalPort 49152-65535 -Action Allow
Allow FTP：控制通道 21，用于登录和命令
Allow FTP Passive：数据通道，范围先放宽，任务 3 收窄
规则名要和原文完全一致，任务 3 的 Set-NetFirewallRule 按 DisplayName 找这条规则。49152-65535 是 Windows 默认的动态端口范围。可用 Get-NetFirewallRule -DisplayName "Allow FTP*" 确认两条都在。
任务 2 · 20′ · DC1

开启用户隔离并设置目录权限

IIS 管理器›LabFTP›FTP 用户隔离›用户名目录(禁用全局虚拟目录)›应用

icacls C:\FTPRoot\LocalUser\alice /grant "alice:(OI)(CI)M"
icacls C:\FTPRoot\LocalUser\bob /grant "bob:(OI)(CI)M"
参数含义
(OI)(CI)对子文件和子文件夹继承（第 6 课）
M修改：可读、写、删除自己的文件
FTP 授权规则 + NTFS 权限都允许才能写入，两层缺一不可。
回顾第 7 课"共享权限与 NTFS 取交集"，FTP 也是同样的两层模型：IIS 授权规则是第一层，NTFS 是第二层。改完隔离设置一定要点右侧"应用"，这是最常见的遗漏。
任务 2 · 20′ · CLIENT1

从客户端测试隔离效果

在 CLIENT1（VM3）的命令提示符中，用户 alice，密码 Lab@2026a

echo hello > test.txt
ftp 10.10.10.10
ftp> ls
ftp> put test.txt
ftp> get readme.txt
ftp> bye
命令预期结果
ls只看到 readme.txt，看不到 bob 的目录
put / get显示 226 Transfer complete
第一行 echo 是补充步骤：原文直接 put test.txt，本地没有这个文件会报错。Windows 自带 ftp 只会主动模式（服务器连回客户端），第一次 ls 时 CLIENT1 会弹出"Windows 安全中心警报"，必须点"允许访问"，否则 ls 卡在"150 Opening ASCII mode data connection"。get 下载的 readme.txt 内容应是 "Alice's file"。再用 bob 登录一次，对比两人看到的内容，让学生体会隔离。提问：在 alice 会话中执行 cd .. 会怎样？
任务 3 · 20′ · DC1

启用 FTPS：强制 SSL 连接

IIS 管理器›LabFTP›FTP SSL 设置

SSL 证书

选择第 11 课创建的 Lab SSL Cert

SSL 策略

选择"需要 SSL 连接"，点右侧"应用"

预期现象：Windows 自带的 ftp 命令不支持 SSL，此后再用它登录会被拒绝（提示策略要求 SSL）。这恰好证明明文登录已被禁止。
下拉框里看不到 Lab SSL Cert，说明第 11 课证书没建或建在了别的存储位置。要测试 FTPS 登录，需要支持 FTPS 的客户端（如 FileZilla，选"要求显式 FTP over TLS"），自签名证书会弹出信任提示。若机房没有此类客户端，以"明文被拒"作为验证即可。
任务 3 · 20′ · DC1

固定被动端口范围并收窄防火墙

IIS 管理器›服务器级别（DC1）›FTP 防火墙支持›数据通道端口范围 50000-50100

Set-NetFirewallRule -DisplayName "Allow FTP Passive" `
  -LocalPort @(50000..50100)
# IIS 自带的被动规则放行 1024-65535，必须禁用
Disable-NetFirewallRule `
  -DisplayName "FTP 服务器被动(FTP 被动流量入站)"
Restart-Service ftpsvc
为什么要固定：启用 SSL 后数据通道被加密，防火墙看不到 PASV 回应里的端口号，只能按预先约定的范围放行。
必须在服务器节点（不是 LabFTP 站点节点）设置端口范围，原文写"服务器级别"。Restart-Service ftpsvc 是补充步骤，服务器级端口范围通常需要重启 FTP 服务才生效，只影响 FTP 服务、不影响其他网站。端口从约 1.6 万个缩小到 101 个，这就是"最小开放"原则。真机实测：安装 FTP 时 IIS 会自动建并启用"FTP 服务器被动(FTP 被动流量入站)"规则，它对 FTP 服务放行 1024-65535，不禁用它，Allow FTP Passive 收得再窄也没用——这正好是讲"防火墙规则是叠加的、任一条允许就放行"的好例子。
排障

FTP 连不上？按这个顺序查

现象原因处理
连接超时21 端口未放行或服务未启动查 Allow FTP 规则，Get-Service ftpsvc
能登录，ls 卡住数据通道端口被拦核对被动端口范围与防火墙一致
530 登录失败未开基本验证或无隔离目录检查验证方式和 LocalUser\用户名
550 / put 被拒授权或 NTFS 无写权限授权规则加写入，重做 icacls
534 要求 SSL客户端不支持 FTPS属正常现象，换支持 TLS 的客户端
先让学生看 FTP 返回码再猜原因：5xx 是服务器拒绝，超时是网络/防火墙。控制通道和数据通道分开排查是本课最重要的排障思路。
