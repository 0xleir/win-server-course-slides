这是整门课的高潮，但不是组间对抗：你自己打自己搭建的环境，先当攻击者把能找到的问题都打一遍，再切回防御者视角，看自己的日志能不能发现刚才那些攻击动作。这个"自己打自己"的设计看似简单，其实价值很高——你知道自己做了什么，所以能精确算出"检测率"（日志里查到了几成），这比猜测更有说服力。全程强调法律与道德边界——只攻击自己的实验网段，严禁触碰任何真实或未授权系统。

阶段 1 · 攻击视角 · 40′

切到 Kali：信息收集 → 利用

在 Kali（10.10.10.50）对自己的靶机操作 · DC1=.10 SVR2=.20 CLIENT1=.100

nmap -sV -p- 10.10.10.10 10.10.10.20 10.10.10.100   # 全端口+服务侦察
nmap -p445 --script smb2-security-mode 10.10.10.20   # SMB 签名是否"强制"
curl -k -o /dev/null -w "%{http_code}
" https://10.10.10.20/  # 网站匿名=401?
curl http://10.10.10.20/                              # 80 端口匿名返回什么
curl -k --ssl-reqd ftp://10.10.10.20/                 # FTP 匿名(应被拒)
sudo mount.cifs //10.10.10.20/IT-Share /mnt -o user=sunqi,pass=错密码,dom=LAB
加固后你会发现：多数口子已关（FTP 要 SSL、网站 443 要认证、CLIENT1 的 RDP 被过滤），但仍有可记录的问题 —— 见 📋 详细步骤。每条都截图进《渗透测试报告》。
方法论就是前面几节课的综合：先 nmap -sV -sC 侦察，再按发现的服务选利用方式——SMB 枚举共享、Hydra 喷射弱口令、http-enum 找 Web 目录、FTP 试匿名。TARGET 替换成你自己 DC1/SVR2 的真实 IP。强调每一步都要留证据，报告质量占分。再次重申只打 10.10.10.0/24 内自己的机器。

攻击的同时，顺手记一下监控对象

监控对象关注点

SVR2 · IIS/FTP 日志C:\inetpub\logs 里 10.10.10.50 的大量请求 = 扫描/枚举

先别急着看：这页只是提前标出阶段3要核对的三条战线，阶段1的重点仍是攻击，等阶段2再切回来逐条查。
这页是为阶段 3 的复盘做铺垫：攻击时你走了哪些路，等下就该去这三条战线里找痕迹。三条战线覆盖域控认证、应用服务、网络与进程，基本能盖住阶段 1 用到的所有攻击手法。先记在心里，阶段 1 结束后再切回防御视角逐条查。
阶段 2 · 切回防御 · 20′

应急响应

① 识别从日志定位攻击源 IP
→
② 封禁防火墙阻止该 IP
→
③ 恢复解锁合法账户
→
④ 修复堵住被利用的漏洞

New-NetFirewallRule -DisplayName "Block-Attacker" -Direction Inbound `
  -RemoteAddress <Kali的IP 10.10.10.50> -Action Block
Search-ADAccount -LockedOut | Unlock-ADAccount
应急响应是一条标准流程：先从日志里确认攻击源 IP（就是你自己的 Kali，10.10.10.50），用防火墙 New-NetFirewallRule 建一条入站 Block 规则封掉它（实测可建可删）；再 Search-ADAccount -LockedOut 看有没有合法用户被喷射误锁，用 Unlock-ADAccount 恢复；最后针对本课真实发现做修复：关掉 SVR2:80 那个匿名的默认 IIS 站点、把 SMB 签名从"启用"改成"强制"、评估是否需要 135/139。封禁要精准到攻击 IP，不要一刀切断全网。
阶段 3 · 复盘 · 20′

对照"我做了什么"和"日志查到了什么"

翻出《渗透测试报告》

  • 我发现了哪些漏洞
  • 我利用了什么攻击路径
  • 哪一步最关键

翻出《安全事件分析报告》

  • 日志里检测到了哪些攻击
  • 遗漏了什么、为什么
  • 响应是否及时
自我检测率：日志里查到的攻击动作数 ÷ 自己实际做过的攻击动作数，算出一个百分比。
复盘是学习价值最高的环节：你自己知道究竟发起了多少次攻击、用了哪些手法，这是"自我检测率"能被精确计算出来的前提——这比两人对抗时"猜对方打了几次"更可靠。遗漏往往比抓到更有教学意义——"为什么没发现"直指防御盲区，比如 FTP 日志没开、Sysmon 配置没覆盖某个事件类型。
评分

评分规则（教师评分，不设组间加权）

评分项分值评分方
发现漏洞数（每个 5 分，上限 25 分）25 分教师
自我检测率（日志查到的攻击 ÷ 自己实际发起的攻击）25 分教师核对两份报告
应急响应速度和完整性25 分教师
报告质量（两份报告的结构、证据、改进建议）25 分教师
漏洞要有证据才算；检测率看《安全事件分析报告》对照《渗透测试报告》里记录的真实攻击次数。总分 = 四项直接相加，不设小组或角色加权。
四项各 25 分，全部由教师评定，不再有"组间互评"。发现漏洞必须有截图/日志证据，口说无凭。自我检测率是检测到的攻击次数除以自己实际发起的攻击次数，所以两份报告都要如实记录——弄虚作假反而会让自己的检测率看起来"异常完美"，教师核对两份报告的时间戳和内容就能发现。应急响应看封禁是否及时准确、合法用户是否恢复。报告质量包含结构、证据、改进建议。把这张表提前公布，学生才知道往哪使劲。
边界 + 排障

纪律红线与常见问题

🚫 红线：只攻击自己的实验网段 10.10.10.0/24，严禁扫描/攻击实验环境之外的任何系统，违者按违纪处理并可能承担法律责任。
现象处理
Kali 连不上目标确认目标 VM 已开机，检查网络连通（同一 Host-only 网段）
日志里什么都没有确认审核策略、Sysmon、pfirewall 日志已开
封禁后攻击仍在继续核对规则方向 Inbound 与来源 IP（10.10.10.50）是否正确
合法用户被锁登不上Unlock-ADAccount 解锁
把红线放在最醒目位置，开课和结束各强调一次。排障方面：日志为空通常是前面某课的审核/日志配置被快照回滚了，要先补上才有东西可看，这也是为什么前面每课都强调开日志、拍快照。封禁无效多半是方向或 IP 写错。
