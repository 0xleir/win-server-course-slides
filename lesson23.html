概念 1

自签名证书 vs CA 签发证书

自签名（第 11 课的做法）

  • 服务器"自己给自己作保"
  • 客户端没有理由相信它
  • 浏览器报警告，用户习惯点"继续"
  • 中间人伪造证书时，用户也分不出来

企业 CA 签发（今天）

  • 由受信任的 Lab-Root-CA 作保
  • 客户端信任根 CA → 自动信任它签的证书
  • 没有警告；一旦出现警告就值得警惕
  • 证书可集中颁发、续订、吊销
一句话：证书的价值不在加密本身，而在"谁为它担保"。
自签名证书一样能加密，问题是无法证明身份。提问：如果用户已经习惯点"继续访问"，攻击者在中间伪造一张证书，用户会发现吗？这就是为什么企业要建 CA：让正常情况没有警告，异常情况才有警告。

概念 3

企业 CA 与证书模板

企业根 CA：Lab-Root-CA（DC1）
已发布的证书模板
📄 Lab Web Server📄 Computer📄 User
模板的"安全"选项卡
👥 Domain Computers：注册
类型特点
企业 CA集成 AD，用模板 + 权限控制颁发，支持自动注册
独立 CA不依赖 AD，申请需手工审批
模板规定证书用途、有效期、谁能申请
模板要经过 复制 → 设置权限 → 发布到 CA 三步，漏掉任何一步都申请不到。
把模板类比成"证件申请表格"：CA 只受理已发布的表格，表格上写明谁有资格申请。不要直接修改预定义的 Web Server 模板，而是复制一份，这样出错可以回退。模板权限配置过宽是现实中 AD CS 被攻击的常见原因，可以课后了解，但实验中不做利用。
任务 1 · 22′ · DC1

安装 AD CS 角色

和 AD DS 一样分两步：先装"程序文件"，再配置成 CA。

在 DC1 上，以 LAB\Administrator 运行 PowerShell

Install-WindowsFeature AD-Certificate `
    -IncludeManagementTools -IncludeAllSubFeature

# 确认结果：Install State 应为 Installed
Get-WindowsFeature AD-Certificate
-IncludeAllSubFeature：连同 Web 注册等子角色一起装；-IncludeManagementTools：装上 certsrv.msc 等控制台。
必须用域管理员（企业管理员）登录，企业 CA 要往 AD 配置分区写信息，本地账号会失败。Get-WindowsFeature 这一行是补充的确认命令。等待安装时，可以先在浏览器打开 https://www.lab.local，记下现在看到的证书警告，作为"课前"对照。
任务 1 · 22′ · DC1

配置企业根 CA 并验证


$ksp = "RSA#Microsoft Software Key Storage Provider"
$ca = @{
  CAType = "EnterpriseRootCA"; CryptoProviderName = $ksp
  KeyLength = 2048; HashAlgorithmName = "SHA256"
  CACommonName = "Lab-Root-CA"; ValidityPeriod = "Years"
  ValidityPeriodUnits = 10
}
Install-AdcsCertificationAuthority @ca -Force
验证命令看到这个说明成功
certutil -ping显示 DC-01.lab.local\Lab-Root-CA，接口处于活动状态（DC-01 换成你自己的 DC 计算机名，即第 1 课的 DC-学号）
Get-Service CertSvcStatus = Running
这里用 @splatting 把原文的长命令拆成哈希表，参数和取值与原文完全一致。CA 名称一旦确定就不能改，打错只能卸载重装，执行前再核对一遍 Lab-Root-CA 拼写。参数要点：EnterpriseRootCA 与 AD 集成才支持模板和自动注册；SHA256 替代已不安全的 SHA1；根证书 10 年要长于它签发的 1 年证书。提醒：谁拿到 CA 私钥就能给任何名字签"真证书"，所以生产环境根 CA 通常离线保存。
任务 2 · 27′ · DC1

复制并发布模板 Lab Web Server


certutil -CATemplates  # 查看 CA 已发布的模板
certtmpl.msc           # 打开"证书模板"控制台
certtmpl.msc›右键 Web Server›复制模板

① 常规

名称 Lab Web Server
有效期 1 年

② 安全

添加 Domain Computers
勾选"注册"

③ 发布到 CA

certsrv.msc › 右键"证书模板" › 新建 › 选 Lab Web Server
在 DC1 上完成这三步。发布后再运行一次 certutil -CATemplates，列表中应出现新模板（显示的是模板内部名，通常不带空格），这就是"复制—权限—发布"三步都完成的证据。常见错误：在 certtmpl.msc 改完就去申请，忘了在 certsrv.msc 里发布。
任务 2 · 27′ · IIS 服务器

为 IIS 申请域证书

IIS 管理器›服务器节点›服务器证书›创建域证书
向导字段填写
通用名称www.lab.local ← 必须与访问地址一致
组织Lab Company
联机证书颁发机构DC-01.lab.local\Lab-Root-CA（点"选择"）
友好名称Lab-Web-Cert
"创建域证书"会直接向企业 CA 在线申请，不用手工导出 CSR 再提交。
在 SVR2 的 IIS 管理器里操作。"服务器证书"图标在左侧树的服务器节点（不是站点节点）下。通用名称填错是最常见错误，填成 DC1 或 IP 地址会导致"名称不匹配"。完成后列表里应出现 Lab-Web-Cert，颁发者为 Lab-Root-CA。

绑定新证书并验证

CompanySite›绑定›编辑 https 443›SSL 证书：Lab-Web-Cert

确认绑定（补充）


Get-WebBinding -Name CompanySite `
    -Protocol https

在 CLIENT1 访问

https://www.lab.local

点地址栏锁图标 › 证书 › 证书路径，应看到 Lab-Root-CA

此时仍有警告是正常的：CLIENT1 还没信任 Lab-Root-CA，任务 3 用 GPO 解决。
原文写"如果 CA 证书已分发"才不再有警告。企业根 CA 安装时会把根证书发布到 AD，域成员刷新组策略后通常会自动信任，所以此时有的环境已无警告，有的还有，两种都正常。等 DC1、SVR2、CLIENT1 都做完之后，最后再切到 Kali 上用浏览器访问同一地址：Kali 不是域成员，会一直看到"不受信任"，讨论这说明了什么。
任务 3 · 18′ · DC1

GPO：证书自动注册

gpmc.msc › 编辑 Default Domain Policy：

计算机配置›策略›Windows 设置›安全设置›公钥策略

双击"证书服务客户端 - 自动注册"

  • 配置模型：已启用
  • 续订过期证书……
  • 更新使用证书模板的证书

效果

域内计算机刷新策略后，会按模板权限自动申请、自动续订证书，管理员不必逐台操作。

在 DC1 上操作。自动注册只对勾选了"自动注册"权限的模板生效；本课模板只给了"注册"权限，所以 Lab Web Server 仍需手工申请——可以作为思考题：如果要让所有服务器自动拿到 Web 证书，模板安全选项卡还要改什么？答案是给 Domain Computers 再勾"自动注册"。
任务 3 · 18′ · DC1 + CLIENT1

GPO：分发根 CA 证书

同一 GPO›公钥策略›受信任的根证书颁发机构›右键 导入

先导出根证书（补充）


certutil "-ca.cert" C:\Lab-Root-CA.cer

-ca.cert 必须加引号（PowerShell 会把带点的参数拆成两个）；然后在导入向导中选这个 .cer 文件

CLIENT1 上刷新验证


gpupdate /force

再次访问 https://www.lab.local，应无警告

原文只写"导入 Lab-Root-CA 证书"，没说证书文件从哪里来；certutil -ca.cert 是补充的导出方法，只读不改 CA。实测在 PowerShell 里不加引号会报"参数太多"、不生成文件：PowerShell 把 -ca.cert 拆成了 -ca 和 .cert 两个参数，所以课件写成 certutil "-ca.cert"（在 cmd 里则不用引号）。导入时证书存储区保持"受信任的根证书颁发机构"。在 CLIENT1 上可运行 certlm.msc 查看本地计算机的受信任根列表中是否出现 Lab-Root-CA。

现象原因处理
向导里找不到 Lab-Root-CACertSvc 未运行 / 非域账号certutil -ping；用 LAB\Administrator

本课小结

为什么

自签名证书无人担保；企业 CA 让域内电脑自动信任

怎么做

装 AD CS → 根 CA → 复制并发布模板 → IIS 申请绑定 → GPO 分发

关键点

信任链 + 名称匹配 + 有效期，三者缺一都会警告
