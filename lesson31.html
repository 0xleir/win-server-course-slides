概念

如何做服务器规划

① 命名

  • 名字体现用途：DC1、SVR2
  • 部门 OU 统一后缀 -Dept
  • 组名统一前缀 Domain-

② IP

  • 服务器用静态 IP
  • 客户端走 DHCP .100–.200
  • 所有机器 DNS → 10.10.10.10

③ 角色分配

  • DC 只放身份类服务
  • 业务服务放成员服务器
  • 一台挂了不拖垮全部

反例

所有服务堆在 DC1：Web 被攻破 = 域被攻破

正例

Web、文件在 SVR2：被攻破也还隔着一层

这三条原则是本稿补充的通用做法。重点讲第三条：IIS 是最常被攻击的服务，和 AD 放在同一台机器上，Web 漏洞就直接威胁域控，这就是原文把 IIS 迁到 SVR2 的原因。DHCP 和 CA 留在 DC1 是本实验为节省 VM 的折中，可以提问学生：生产环境 CA 应该放哪？

任务 3 · 13′ · CLIENT1 / DC1

互通与域环境验证（只读命令）


# 先在 CLIENT1 上：网络互通 + 找得到域
Test-NetConnection 10.10.10.10 -Port 389
Test-NetConnection 10.10.10.20 -Port 445
nltest /dsgetdc:lab.local
# 再切到 DC1：确认所有机器都在域中
Get-ADComputer -Filter * | Select-Object Name, Enabled
命令预期结果
Test-NetConnection ...389（DC1）TcpTestSucceeded : True
Test-NetConnection ...445（SVR2）False（SVR2 未装文件服务器角色，第32课后变 True）
nltestDC: \\DC-学号.lab.local，命令成功完成
Get-ADComputer列出 DC1、SVR2、CLIENT1
四条命令都是只读的，分别学过：Test-NetConnection 在第 14、16、21 课，nltest 在第 17 课，Get-ADComputer 是 AD 模块的查询命令，与第 18 课 Get-ADOrganizationalUnit 用法一致。389 是 LDAP、445 是 SMB。真机验证过：445 端口在本课阶段必然测不通（SVR2 没有 LanmanServer 入站防火墙规则，要等第 32 课装文件服务器角色才会开），这是正常现象不是故障，别让学生卡在这一条上。你也可以切到 SVR2 上跑一遍 nltest，确认 SVR2 自己能找到域控。排障：端口不通先看 VM 是否开机和第 21 课防火墙规则；nltest 失败先查 DNS 是否指向 10.10.10.10；DHCP 续租超时先查 DC1 的 DHCP 服务器是否已在 AD 中授权（Get-DhcpServerSetting → IsAuthorized，未授权则 Add-DhcpServerInDC）；SVR2 长期关机若报"信任关系失败"，举手找老师，不要自行退域。本课不改配置（DHCP 授权例外，这是基础设施缺陷不是"配置"，必须先修好才能验证任务 3），其余问题记入清单待办，第 32 课处理。
