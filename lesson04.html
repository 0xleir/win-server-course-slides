概念

密码策略六要素（教材释义）

策略项系统释义
强制密码历史重用旧密码前要记住的历史密码个数；用同一密码越久，被暴力破解的机会越大
密码最长使用期限系统要求用户更改密码之前，可以使用该密码的天数
密码最短使用期限用户更改密码之前必须使用的天数；取值须 小于最长使用期限
最短密码长度可以组成账户密码的最少字符数
账户锁定阈值导致账户被锁定的连续登录失败次数
账户锁定时间自动解锁前账户保持锁定的时长（1–99999 分钟，0 = 须管理员手动解锁）
复位账户锁定计数器一次登录失败后，多久没再失败就把失败计数器清零（分钟）
路径：服务器管理器 → 工具 → 本地安全策略 → 账户策略
这张表是教材"必备知识"里对密码策略每一项的标准解释，后面任务配具体数值时就对应这些含义：强制密码历史决定了重用旧密码前要记住几个历史密码，用户用同一个密码时间越长、被暴力破解的机会就越大，所以要限制重用；密码最长使用期限是系统强制你改密码之前能用多少天；密码最短使用期限是你改密码之前必须先用够多少天，它必须小于最长期限，否则就能连续改密码把历史挤掉再改回原密码；最短密码长度规定了密码至少几个字符。后三项是账户锁定策略：账户锁定阈值是连续错几次就锁账户，锁定之后在管理员复位或锁定时间到期前都不能用；账户锁定时间是自动解锁前锁多久，范围 1 到 99999 分钟，设成 0 就表示必须管理员手动解锁；复位账户锁定计数器是一次登录失败后，多久没再失败就把失败计数清零。所有这些都在"服务器管理器→工具→本地安全策略"里设置。

概念 1

密码为什么需要"规则"

没有策略

  • 用户会选 123456、生日、用户名
  • 弱密码在字典里，几秒内被猜中
  • 一个密码用好几年，泄露了也不换
  • 被迫改密码时又改回旧密码

有策略

  • 复杂性：大写/小写/数字/符号任三类
  • 最短长度 8：拉大暴力破解空间
  • 最长期限 90 天：泄露也有期限
  • 历史 5 个 + 最短期限 1 天：防改回旧密码
一句话：策略在"设置密码的那一刻"由系统强制检查，不依赖用户自觉。
提问：为什么需要"最短使用期限 1 天"？答：否则用户可以连续改 5 次把历史挤掉，然后改回原密码。复杂性要求还禁止密码包含用户名。注意策略只在下次设置密码时检查，已有的旧密码不会被强制改。
概念 2

账户锁定：三个参数如何配合

输错密码计数器 +1
→
15 分钟内没再错计数器归零
→
累计到 5 次账户被锁定
→
30 分钟后自动解锁
或管理员手动解锁
参数本课取值作用
账户锁定阈值5 次错几次就锁；0 表示永不锁定
重置账户锁定计数器15 分钟多久不出错就清零计数
账户锁定时间30 分钟锁多久；必须 ≥ 重置时间
锁定策略是对付在线暴力破解的主要手段，但阈值太低会被人恶意锁死别人的账号（拒绝服务），所以要折中。系统要求锁定时间 ≥ 重置计数器时间，设置阈值时 Windows 会自动建议另两项的值。内置 Administrator 默认不受锁定影响，所以测试要用 bob。
概念 3

审计：让操作留下证据

① 开启审计策略secpol.msc
→
② 发生事件登录、建用户…
→
③ 写入安全日志每条带事件 ID
→
④ 查询分析eventvwr / PowerShell
事件 ID含义由哪项审计产生
4624登录成功审核登录事件 · 成功
4625登录失败审核登录事件 · 失败
4720用户账户已创建审核账户管理 · 成功
强调：没开审计就没有记录，出事后再开已经晚了。"成功"和"失败"要分别勾选，只勾成功就看不到 4625 暴力破解痕迹。这三个事件 ID 在后面的日志分析、内网安全课中会反复出现，要求学生记住。
任务 1 · 19′ · DC1

配置密码策略

Win+R 运行 secpol.msc，然后：

安全设置›账户策略›密码策略
策略项设置为
密码必须符合复杂性要求已启用
密码长度最小值8 个字符
密码最短使用期限1 天
密码最长使用期限90 天
强制密码历史5 个记住的密码
双击策略项即可修改。Server 默认已启用复杂性、最长期限 42 天，可以先让学生记下默认值再改，体会"默认并不安全"。改完不需要重启，但可以执行 gpupdate /force 让策略立即刷新。
任务 1 · 19′ · DC1

查看策略并测试弱密码

在 DC1 上，以管理员身份打开 PowerShell

# 查看当前生效的密码与锁定策略
net accounts

# 测试：给 alice 设置弱密码
net user alice 123456
net accounts：最小密码长度 8、最长期限 90、历史 5，与 secpol 一致
预期失败：提示密码不满足密码策略要求（复杂性 / 长度）
如果 net user alice 123456 竟然成功了，说明复杂性没有启用或没有刷新，回到 secpol 检查。可以追问：Lab@2026a 为什么能通过？（大写、小写、数字、符号四类都有，长度 9）。测试完不要把 alice 的密码改乱，后面课程还要用。

任务 2 · 15′ · DC1

检查锁定状态并解锁

① 检查 bob 的状态


net user bob

预期："Account active" 显示 No 或锁定提示

② 解锁账户


net user bob /active:yes

或图形界面操作（见下方路径）

lusrmgr.msc›用户›bob›属性›取消"账户已锁定"
中文系统中这一行显示为"帐户启用"，锁定时可能显示 Locked（已锁定）。如果 net user bob /active:yes 后仍然登录不了，就用 lusrmgr.msc 取消勾选"账户已锁定"，这是最可靠的解锁方式。提问：如果管理员不管，bob 多久后能自己恢复？（30 分钟）
任务 3 · 19′ · DC1

开启审计策略

secpol.msc›本地策略›审核策略
策略项设置为记录什么
审核账户登录事件成功, 失败凭据验证
审核登录事件成功, 失败4624 / 4625
审核对象访问成功, 失败文件等对象（需另设 SACL）
审核策略更改成功, 失败谁改了策略
审核账户管理成功, 失败4720 建用户等
每一项都要同时勾选"成功"和"失败"。"账户登录事件"和"登录事件"名字很像容易混：前者是验证凭据的机器记录，后者是被登录的机器记录，本机实验两者都会产生。对象访问还要在具体文件夹上配置审核项（SACL）才会有日志，第 6 课 NTFS 后可以回头体验。
