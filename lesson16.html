概念

默认端口 3389：方便，也最危险

3389 的风险

  • 远程桌面默认监听 TCP 3389，人尽皆知
  • 直接暴露外网，极易成为攻击目标
  • 自动化扫描器专门扫 3389 做暴力破解
  • 曾有服务器因未改默认端口遭勒索病毒攻击

改默认端口

  • 注册表 PortNumber 改为非 3389
  • 避开针对 3389 的自动化扫描
  • 常规却相对有效的加固手段
  • 需同步放行防火墙新端口
要点：改端口只是"隐藏"，挡不住全端口扫描；必须配合 NLA、强密码、审计、防火墙等纵深防御。
教材补充：远程桌面是网络管理员最常用的工具之一，外网访问时非常方便，但它默认的 3389 端口太容易受到攻击。教材里举了真实案例——有客户的服务器就因为没有更改默认端口而遭到勒索病毒攻击，幸亏提前在别的设备做了备份，只是重装服务器损失了一些时间。所以更改远程桌面的默认端口，是一项常规却相对有效的手段：通过注册表把 PortNumber 从 3389 改掉，就能避开那些专门扫 3389 的自动化攻击工具。但要强调，改端口只是"隐藏入口"，用 nmap 做全端口扫描照样能发现，所以它只是辅助手段，真正的安全还要靠本课后面要做的 NLA、强密码、登录审计、会话限制和防火墙默认阻止等纵深防御。改端口后别忘了在防火墙放行新端口，否则自己也连不上。

概念 1

远程入口就是攻击面

只"能用"的远程访问

  • 任何 IP 都能尝试连接 RDP / WinRM
  • 登录失败不留记录，被暴力破解也不知道
  • 剪贴板、磁盘可随意在两端复制文件
  • WinRM 走 HTTP 5985，依赖 NTLM/Kerberos 加密

加固后的远程访问

  • 防火墙默认阻止，只放行必要端口
  • 登录成功/失败全部审计
  • 限制会话数和空闲断开时间
  • 禁止重定向，WinRM 改走 HTTPS 5986
一句话：改端口（第 14 课）只能挡住扫描器，真正的安全靠层层设卡。
提问：第 14 课把 RDP 改成 3390，算不算安全措施？引导学生说出"只是隐藏，nmap 全端口扫描照样能发现"。RDP 暴力破解是勒索软件最常见的入侵途径之一，可以举新闻案例。

概念 3

WinRM：HTTP 5985 vs HTTPS 5986

对比项HTTP 监听器HTTPS 监听器
端口59855986
传输加密靠认证协议加密消息内容TLS 加密整个通道
服务器身份工作组下无法验证证书证明"我就是 dc1"
需要什么Enable-PSRemoting 即可证书 + 新建监听器 + 放行端口
自签名证书：能加密，但客户端不信任它；正式环境应由 CA 签发（第 23 课 AD CS 会讲）。
第 15 课在工作组里要设 TrustedHosts，正是因为 HTTP 方式无法验证服务器身份。HTTPS 监听器要绑定证书指纹（Thumbprint），证书的 DnsName 应与客户端连接时用的名字一致。
任务 1 · 24′ · DC1

RDP 加固 ①：登录审计

1.1 在 DC1 上，以管理员身份运行（PowerShell 或 cmd）

# 登录 (Logon)
auditpol /set /subcategory:"{0CCE9215-69AE-11D9-BED3-505054503030}" `
  /success:enable /failure:enable
# 其他登录/注销事件 (Other Logon/Logoff Events)
auditpol /set /subcategory:"{0CCE921C-69AE-11D9-BED3-505054503030}" `
  /success:enable /failure:enable
auditpol /get /category:"{69979849-797A-11D9-BED3-505054503030}"   # 登录/注销
4624 / 4625：登录成功 / 失败，RDP 登录类型为 10
4778 / 4779：会话重新连接 / 断开（Other Logon/Logoff）
原文命令是一行写完的，这里用反引号续行以便显示，cmd 中请写成一行。最后一条 auditpol /get 是补充的查看命令，确认两项都是"成功和失败"。让 B 在 CLIENT1 故意输错一次密码，A 在事件查看器"安全"日志中找 4625。子类别名跟系统语言走：中文系统写英文名会报 0x57，所以统一用 GUID（任何语言通用，必须加引号）；中文系统也可以直接写中文名，如 /subcategory:"登录"。

RDP 加固 ②：会话数与超时

运行 gpedit.msc，依次展开：

计算机配置›管理模板›Windows 组件›远程桌面服务›远程桌面会话主机
子节点策略设置
连接限制连接数已启用 · 2
会话时间限制设置已断开会话的时间限制已启用 · 15 分钟
会话时间限制到达时间限制时终止会话已启用
改完执行 gpupdate /force 立即生效
原文路径省略了"Windows 组件"一层，超时策略实际位于"会话时间限制"子节点而不是"连接"，这里按真实位置写。提问：断开会话为什么要限时？因为断开不等于注销，程序和登录令牌仍留在服务器上。gpupdate 是补充的，避免等待策略刷新。
任务 1 · 24′ · DC1

RDP 加固 ③：禁止剪贴板/驱动器重定向

远程桌面服务›远程桌面会话主机›设备和资源重定向

不允许剪贴板重定向

已启用 → 两端之间不能复制粘贴文字和文件

不允许驱动器重定向

已启用 → 远程会话里看不到客户端的 C: 盘

测试：B 在 CLIENT1 用 mstsc /v:10.10.10.10:3390 重新登录，尝试复制粘贴，应当失败。
重定向策略只对新建立的会话生效，已连接的会话要注销后重连才能看到效果。讨论：这两项是防"数据泄露"，也防"把恶意程序带进服务器"。运维人员会抱怨不方便，正式环境通常用跳板机统一文件传输。
任务 2 · 20′ · DC1

WinRM 加固 ①：HTTPS 监听器


$cert = New-SelfSignedCertificate -DnsName "dc1.lab.local" `
  -CertStoreLocation cert:\LocalMachine\My
New-WSManInstance winrm/config/listener `
  -SelectorSet @{Address="*";Transport="HTTPS"} `
  -ValueSet @{CertificateThumbprint=$cert.Thumbprint}
New-NetFirewallRule -DisplayName "Allow WinRM HTTPS" `
  -Direction Inbound -Protocol TCP -LocalPort 5986 `
  -Action Allow
确认：应同时看到 HTTP 和 HTTPS 两个监听器

Get-WSManInstance winrm/config/listener -Enumerate
三条命令必须在同一个 PowerShell 窗口执行，因为 $cert 变量要传下去。原文证书名是 dc1.lab.local，但本课时域还没建，这个名字只是写在证书里，不影响创建监听器。查看监听器的命令来自第 15 课。

WinRM 加固 ②：来源过滤与日志

2.2 只允许实验网段


Set-Item WSMan:\localhost\Service\IPv4Filter `
  -Value "10.10.10.1-10.10.10.254"

2.3 开启操作日志


wevtutil sl "Microsoft-Windows-WinRM/Operational" /e:true
B 在 CLIENT1 上测试 5986 端口是否可达

Test-NetConnection 10.10.10.10 -Port 5986
预期：TcpTestSucceeded : True
注意：IPv4Filter 只认范围写法 IP1-IP2（如 10.10.10.1-10.10.10.254），不能用 10.10.10.* 通配——那是 IIS 的 IP 限制写法，这里会报"IP 筛选器无效"。
IPv4Filter 是服务端的来源白名单，和第 15 课客户端的 TrustedHosts 不是一回事，学生容易混淆，可以提问区分。Set-Item 会提示确认，输入 Y。Test-NetConnection 是补充的只读测试；日志在事件查看器 应用程序和服务日志 › Microsoft › Windows › Windows Remote Management。
任务 3 · 16′ · DC1

防火墙 ①：先审查，再动手


Get-NetFirewallRule -Enabled True |
  Select-Object DisplayName, Direction, Action, Profile |
  Sort-Object Direction | Format-Table

对照下面的清单，确认这些入站放行规则都已存在：

基础服务

DNS · DHCP · ICMP

网站/文件

HTTP/HTTPS · FTP

远程管理

RDP 3390 · WinRM 5986

这一步的意义：下一页把默认入站改为阻止后，没有放行规则的服务会立刻不通。缺哪条规则先补上再继续，否则 B 的远程连接可能被断开，只能回 VM 控制台操作。
任务 3 · 16′ · DC1

防火墙 ②：默认阻止入站 + 备份


Set-NetFirewallProfile -Profile Domain,Public,Private `
  -DefaultInboundAction Block -DefaultOutboundAction Allow
Get-NetFirewallRule -Enabled True -Direction Inbound |
  Format-Table DisplayName, LocalPort
netsh advfirewall export C:\LabFiles\firewall-backup.wfw
白名单思维：没被明确允许的入站，一律拒绝
备份：改坏了可用 netsh advfirewall import 还原
注意 Get-NetFirewallRule 的结果对象并没有 LocalPort 属性，这一列会显示为空，原文命令保留；想看端口可补充用 Get-NetFirewallPortFilter。建议 A 操作 DC1 控制台而不是通过 RDP 执行这一步，避免把自己锁在外面。改完让 B 再测一次 mstsc 和 5986。
排障

加固后连不上？按这个顺序查

现象原因处理
改默认阻止后 RDP 断开缺少 3390 放行规则在 VM 控制台补规则，或 import 备份
第 3 个 RDP 用户被拒限制连接数 = 2，属预期注销一个已断开的会话
剪贴板仍能用旧会话 / 策略未刷新gpupdate /force 后重新登录
New-WSManInstance 报错HTTPS 监听器已存在或 $cert 为空先 Enumerate 查看；同一窗口重建证书
5986 测试 False防火墙规则或 IPv4Filter 不对检查规则和 10.10.10.1-10.10.10.254
第一行是本课最容易出的事故，强调永远通过 VM 控制台做防火墙改动。第二行很多学生会误以为是故障，其实恰好证明策略生效了，可以作为演示：A、B 加上老师同时连，第三个被拒。
