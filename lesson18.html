概念

域用户 vs 本地用户 · 域账户数据库

对比项本地用户域用户
存放位置本机 SAM 数据库域控统一的 ntds.dit
验证者所在计算机自己域控制器（DC）集中验证
可登录范围只能登录本机任意加入域的计算机
管理方式逐台单独管理在 DC 上集中管理授权

域账户数据库 ntds.dit

  • 域账户数据库，路径 C:\Windows\NTDS\ntds.dit，保存全域账户与密码
  • 机器提升为域的第一台 DC 时，原 SAM 数据库升级到此
  • 此后本地用户账户变成域用户账户，由 DC 统一验证
先讲区别：本地用户存在每台电脑自己的 SAM 库里，只能登录这一台机器，谁管谁的；域用户统一存在域控的 ntds.dit 数据库里，由 DC 集中验证，一个账号可以登录域内任何一台加入域的电脑，管理也集中在 DC 上做。再讲 ntds.dit——它就是域的账户数据库，路径在 C:\Windows\NTDS\ntds.dit，里面装着全域的账户和密码信息。一个很重要的转折点：当一台计算机被提升为这个域的第一台域控时，它原来的 SAM 数据库会升级到 ntds.dit，原来的本地用户账户也就随之变成了域用户账户。所以域控上通常看不到普通意义的"本地用户"。顺便提一句部署时设置的"目录服务还原模式密码"，它只在还原模式下登录才用，因为那种模式下所有域账户都不能用。

概念 1

默认容器 vs 组织单元 OU

默认容器 CN=Users

  • 装域时自动生成，所有人挤在一起
  • 不能挂组策略 GPO
  • 不能按部门委派管理权
  • 不能在里面再建 OU

组织单元 OU=IT-Dept

  • 按部门、地点自由规划层级
  • 可以挂 GPO（第 19 课）
  • 可以把管理权委派给部门管理员
  • 默认开启"防止意外删除"
一句话：OU 是域里"能挂策略、能分权"的文件夹；容器只是个存放区。
打开 dsa.msc 对比：Users 是普通文件夹图标，OU 图标上多了一个小册子。提问：上节课 SVR2、CLIENT1 加域后，计算机账户放在哪里？答：CN=Computers 容器，所以不能直接对它们挂 GPO。
概念 2

今天要建的 OU 结构与 DN 路径

域 lab.local（DC=lab,DC=local）
OU=Company
📁 IT-Dept📁 Finance-Dept 📁 HR-Dept📁 Servers
对象DN（从里往外写）
CompanyOU=Company,DC=lab,DC=local
IT-DeptOU=IT-Dept,OU=Company,
DC=lab,DC=local
wangweiCN=Wang Wei,OU=IT-Dept,…
规律：DN 像倒着写的地址，最具体的放最左边；-Path 写的是"放到哪个父级"。
类比邮寄地址：先写房间号再写楼、再写城市。-Path 填的是父级 DN，不含对象自己的名字；所以建 Company 时 Path 是域根，建 IT-Dept 时 Path 是 Company。逗号前后不能有多余空格或中文逗号。
概念 3

组管"能访问什么"，委派管"能管理谁"

概念本课取值作用
组类型Security 安全组可以出现在权限列表 ACL 里（通讯组不行）
组作用域Global 全局组按部门归类本域用户，最常用
委派wangwei → IT-Dept在 OU 的 ACL 上给普通用户加管理权限
域管理员管整个域
→
委派只授权 IT-Dept
→
wangwei能管 IT-Dept
不能碰 Finance-Dept
委派体现最小权限原则：wangwei 不需要成为 Domain Admins 也能完成部门日常工作（建账号、重置密码）。组作用域还有本地域组和通用组，课上只点到，AGDLP 原则可留作课后阅读。提问：为什么不直接把 wangwei 加进 Domain Admins？
任务 1 · 15′ · DC1

创建 OU 结构

先建父级 Company，再在它下面建 4 个部门 OU

New-ADOrganizationalUnit -Name "Company" `
  -Path "DC=lab,DC=local"
$p = "OU=Company,DC=lab,DC=local"
$ous = "IT-Dept","Finance-Dept","HR-Dept","Servers"
foreach ($o in $ous) {
  New-ADOrganizationalUnit -Name $o -Path $p
}
确认删除保护：ProtectedFromAccidentalDeletion 应全为 True

Get-ADOrganizationalUnit -Filter * |
  Select-Object Name, ProtectedFromAccidentalDeletion
原文是 5 条独立的 New-ADOrganizationalUnit，这里用 foreach 循环写后 4 条，效果完全一样，也可以让学生逐条敲。顺序不能反：先有 Company 才能在它下面建子 OU，否则报"找不到目录对象"。输出里还会看到默认的 Domain Controllers OU，这是正常的。
任务 2 · 23′ · DC1

创建第一个域用户 wangwei


$pw = ConvertTo-SecureString "Domain@2026!" `
  -AsPlainText -Force
New-ADUser -Name "Wang Wei" -SamAccountName "wangwei" `
  -UserPrincipalName "wangwei@lab.local" `
  -Path "OU=IT-Dept,OU=Company,DC=lab,DC=local" `
  -AccountPassword $pw -Enabled $true `
  -Department "IT" -Title "系统管理员"
参数含义
-SamAccountName旧式登录名，写作 LAB\wangwei
-UserPrincipalName新式登录名 wangwei@lab.local
-Enabled $true不写这个，账户默认是禁用的
-Name 是显示名，会成为 DN 里的 CN=Wang Wei；真正登录用的是 SamAccountName 或 UPN。不设密码或密码不满足域复杂度策略时会报错，Domain@2026! 满足要求。建完到 dsa.msc 里刷新 IT-Dept 看一眼。

你自己准备好这个文件就行：先用记事本建好 CSV，再写导入脚本。重点：列名必须和脚本里 $_.xxx 完全一致，多一个空格就取不到值。Title 列有中文，编码不对会变成乱码，见排障页。
任务 2 · 23′ · DC1

导入脚本：一行 CSV 建一个用户

沿用上一页的 $pw（密码 Domain@2026!）

Import-Csv C:\LabFiles\domain-users.csv | ForEach-Object {
  $sam = $_.SamAccountName
  New-ADUser -Name $_.Name -SamAccountName $sam `
    -UserPrincipalName "$sam@lab.local" -Enabled $true `
    -Path "OU=$($_.OU),OU=Company,DC=lab,DC=local" `
    -AccountPassword $pw -Department $_.Department `
    -Title $_.Title; Write-Host "Created: $sam" -Fore Green
}
预期：屏幕出现 5 行绿色 Created: …；任何一行红字都要先看是哪个用户、哪个参数。
原文脚本在循环里每次重新 ConvertTo-SecureString，这里为了缩短行宽复用 $pw，并把 SamAccountName 存进 $sam，逻辑完全一致。如果新开了 PowerShell 窗口，$pw 已经不存在，要先重新执行上一页第一条命令。重复运行会报"指定的帐户已存在"，不影响已建成的用户。
任务 2 · 23′ · DC1

创建部门安全组并加成员


$it  = "OU=IT-Dept,OU=Company,DC=lab,DC=local"
$fin = "OU=Finance-Dept,OU=Company,DC=lab,DC=local"
New-ADGroup -Name "Domain-IT" -GroupScope Global `
  -GroupCategory Security -Path $it
New-ADGroup -Name "Domain-Finance" -GroupScope Global `
  -GroupCategory Security -Path $fin


Add-ADGroupMember -Identity "Domain-IT" `
  -Members "wangwei","sunqi"
Add-ADGroupMember -Identity "Domain-Finance" `
  -Members "zhangsan","lisi"
-Members 用的是 SamAccountName，不是显示名 Wang Wei。HR 部门的 wangwu、zhaoliu 原文没有建组，可以作为课后练习让学生自己建 Domain-HR。可用 Get-ADGroupMember "Domain-IT" 现场核对成员。
任务 3 · 15′ · DC1

把 IT-Dept 委派给 wangwei

dsa.msc›Company›右键 IT-Dept›委派控制›添加 wangwei

勾选这三项委派任务

  • 创建、删除和管理用户账户
  • 重置用户密码并强制在下次登录时更改密码
  • 修改组成员身份
注意：一定是在 IT-Dept 上右键，不是 Company，否则 wangwei 会管到所有部门。
向导里的任务名称与原文略有差异："重置用户密码"在界面上完整写作"重置用户密码并强制在下次登录时更改密码"，"管理组成员身份"对应"修改组成员身份"。委派向导本质是往 OU 的 ACL 里写 ACE，可以在 IT-Dept 属性 → 安全 → 高级中看到 wangwei 的条目（需先在"查看"菜单开启高级功能）。
任务 3 · 15′ · DC1

用 wangwei 的身份测试委派边界


$cred = Get-Credential   # 输入 wangwei@lab.local
$tp = ConvertTo-SecureString "Test@2026!" `
  -AsPlainText -Force
$it = "OU=IT-Dept,OU=Company,DC=lab,DC=local"
$fin = "OU=Finance-Dept,OU=Company,DC=lab,DC=local"
$a = @{AccountPassword=$tp; Enabled=$true}
$a.Credential = $cred
New-ADUser "Test Delegate" -SamAccountName testdel `
  -Path $it @a
New-ADUser "Test Delegate2" -SamAccountName testdel2 `
  -Path $fin @a

testdel → IT-Dept

预期：成功

testdel2 → Finance-Dept

预期：拒绝访问（无 Finance-Dept 权限）

你刚做完委派，现在自己用 -Credential 以 wangwei 身份测试，亲自判断结果。第二条报"拒绝访问"才是正确结果，要提醒学生不要以为是自己做错了，这正是权限边界生效的证据。$a 是参数哈希表，@a 把它展开成 -AccountPassword/-Enabled/-Credential（称为 splatting），可借此顺带介绍。-Credential 让命令以 wangwei 身份执行，而当前窗口仍是 Administrator。
排障

报错了？先对照这张表

现象原因处理
找不到目录对象-Path 的 DN 写错或父 OU 未建对照概念 2 的 DN 表，检查逗号和拼写
指定的帐户已存在脚本重复运行已建好的用户不受影响，忽略即可
密码不符合要求不满足域密码复杂度使用原文密码 Domain@2026!
Title 显示乱码CSV 编码不是 UTF-8记事本"另存为"选 UTF-8
testdel 也被拒绝委派做在了别的 OU 或漏勾任务在 IT-Dept 上重新运行委派向导
删除 OU 报"拒绝访问"？那是删除保护在起作用，说明配置正确。
先让学生把报错的第一行读出来再查表。DN 写错是本课最高频问题，尤其是把 OU=Company 漏掉。不要为了"重做"去关闭删除保护再删 OU，回滚快照更安全。

本课小结

为什么

OU 能挂策略、能分权；委派让部门自管而不必给域管权限

怎么做

New-ADOrganizationalUnit → New-ADUser / CSV → New-ADGroup → 委派控制

关键点

DN 从里往外写；-Path 是父级位置
