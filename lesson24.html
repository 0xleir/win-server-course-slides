概念 1

默认安装 vs 安全基线

默认安装（兼容优先）

  • 为了兼容老设备，保留旧协议
  • 很多服务默认开启，不管用不用
  • 允许匿名查询部分账号信息
  • 审计只记录最基本的事件

安全基线（安全优先）

  • 一份经过验证的推荐配置清单
  • 微软官方发布，按系统版本分别提供
  • 以 GPO 形式提供，可整批导入
  • 是"加固"和"检查"的共同标准
一句话：基线回答"应该是什么样"，检查回答"现在是什么样"，加固就是消除两者的差距。
类比：基线就像装修验收标准，没有标准就谈不上验收。微软的 Security Compliance Toolkit（SCT）里包含 Windows Server 2022 的基线 GPO。提问：为什么微软不直接把默认配置做成最安全的？引导出"兼容性与安全的取舍"。

任务 1 · 27′ · DC1 / SVR2

对照基线检查当前配置

① SMBv1 与远程注册表


Get-SmbServerConfiguration |
  Select-Object EnableSMB1Protocol
Get-Service RemoteRegistry |
  Select-Object Status, StartType

② TLS 1.0 / 1.1


$p = "HKLM:\SYSTEM\CurrentControlSet" +
  "\Control\SecurityProviders\SCHANNEL\Protocols"
Get-ChildItem $p
  • ④ Windows 自动更新：设置 › 更新和安全，看是否已配置更新策略
  • 把四项的"加固前"状态填入对比表
SMBv1 显示 True 就是不合规。SCHANNEL\Protocols 下如果没有 "TLS 1.0" 子项，表示使用系统默认值，并不等于已禁用，这一点学生常误判。在 DC1 做完检查后，切到 SVR2 上做同样的检查。然后再切到 Kali，用 nmap --script smb-protocols -p 445 10.10.10.10 记录"加固前"的协议列表，只扫实验网地址。
任务 2 · 26′ · DC1 / SVR2

禁用 SMBv1 与多余服务

2.1 禁用 SMBv1（服务端开关 + 卸载组件）

Set-SmbServerConfiguration -EnableSMB1Protocol $false -Force
Disable-WindowsOptionalFeature -Online `
  -FeatureName SMB1Protocol -NoRestart
2.2 服务加固

Set-Service -Name "RemoteRegistry" -StartupType Disabled `
  -Status Stopped
Set-Service -Name "Spooler" -StartupType Disabled `
  -Status Stopped        # 如不需要打印
Set-Service -Name "lmhosts" -StartupType Disabled
SMBv1 要两步都做：第一行关掉服务端协议，第二行把组件卸掉，-NoRestart 表示稍后再重启，完全生效需要重启一次。Spooler 是打印后台服务，"打印噩梦"漏洞就出在它身上，DC 上一般不需要打印；如果有打印实验就跳过这一行。你在 DC1 做完后，再切到 SVR2 上做同样的加固。
任务 2 · 26′ · DC1

注册表加固：LSA 三项


$lsa = "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa"
# 禁用匿名 SID 枚举
Set-ItemProperty $lsa -Name RestrictAnonymousSAM -Value 1
# 禁用空会话
Set-ItemProperty $lsa -Name RestrictAnonymous -Value 1
# LAN Manager 身份验证级别（仅 NTLMv2）
Set-ItemProperty $lsa -Name LmCompatibilityLevel -Value 5
值名称设为含义
RestrictAnonymousSAM1匿名用户不能枚举 SAM 账户
RestrictAnonymous1匿名用户不能枚举账户和共享
LmCompatibilityLevel5只发 NTLMv2，拒绝 LM 和 NTLMv1
用变量 $lsa 代替原文中重复的长路径，效果完全相同。改注册表前提醒：只改这三个值，不要动 Lsa 下的其他项，改错可能导致无法登录。LmCompatibilityLevel=5 是 阶段考核 4 的 B3 考点，也和第 28 课的哈希破解直接相关。
任务 2 · 26′ · DC1

审计策略（增强）


$ok = "/success:enable"
$on = $ok, "/failure:enable"
auditpol /set /subcategory:"{0CCE923F-69AE-11D9-BED3-505054503030}" $on  # 凭据验证
auditpol /set /subcategory:"{0CCE922B-69AE-11D9-BED3-505054503030}" $ok  # 进程创建
auditpol /set /subcategory:"{0CCE9215-69AE-11D9-BED3-505054503030}" $on  # 登录
auditpol /set /subcategory:"{0CCE921B-69AE-11D9-BED3-505054503030}" $ok  # 特殊登录
子类别记录典型事件 ID
凭据验证 Credential Validation成功 + 失败4776 凭据验证
进程创建 Process Creation成功4688 新进程创建
登录 Logon成功 + 失败4624 登录成功 / 4625 登录失败
特殊登录 Special Logon成功4672 分配特权登录
PowerShell 会把数组变量 $on 展开成两个独立参数，等价于原文的 /success:enable /failure:enable；$ok 就是 /success:enable。验证用 auditpol /get /category:* 查看。中文系统只认中文子类别名，写英文名（Logon 等）会报 0x57，所以这里统一用 GUID（任何语言通用），GUID 必须加引号。这些事件 ID 要记住，第 29 课日志分析时要靠它们找出暴力破解痕迹。
任务 3 · 18′ · DC1

安全检查报告 ①：采集数据

在 ISE 或记事本中新建 C:\Scripts\SecurityReport.ps1，先写采集部分：


$key = "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa"
$smb = (Get-SmbServerConfiguration).EnableSMB1Protocol
$fw  = Get-NetFirewallProfile -Profile Domain |
  Select-Object -ExpandProperty DefaultInboundAction
$mp  = (Get-MpComputerStatus).RealTimeProtectionEnabled
$ca  = (Get-Service CertSvc).Status
$aud = auditpol /get /subcategory:"{0CCE9215-69AE-11D9-BED3-505054503030}" 2>&1
$lm  = (Get-ItemProperty $key).LmCompatibilityLevel
为什么不照抄原文的 @" … "@ | Out-File：双引号里的 $(…) 会在生成文件时就被求值，文件里写进去的是"当时的结果"，以后再运行也不会变。
检查项与原文完全一致：SMBv1、域配置文件默认入站动作、Defender 实时保护、CA 服务、登录审计、LmCompatibilityLevel，只是改成先存变量、再输出，便于阅读。如果坚持用 here-string 生成，要改成单引号 @' '@，内容才会原样写入。写完脚本后对照检查每一行的拼写。
任务 3 · 18′ · DC1

安全检查报告 ②：输出并运行


$t = "=== Windows Server Security Check ==="
Write-Host $t -ForegroundColor Cyan
Write-Host "SMBv1: $smb"
Write-Host "Firewall Default Inbound: $fw"
Write-Host "Defender Real-time: $mp"
Write-Host "CA Service: $ca"
Write-Host "Audit Logon: $aud"
Write-Host "LmCompatibilityLevel: $lm"
保存后运行：C:\Scripts\SecurityReport.ps1
把这 8 行接在上一页的采集代码后面，保存为同一个文件。运行时如果提示脚本被执行策略阻止（在此系统上禁止执行脚本），用 Set-ExecutionPolicy -Scope Process RemoteSigned 对当前窗口放行即可。下一页给出加固后应该看到的结果。

报告项期望值不是这个值说明

排障

加固出问题？按这个表查

现象原因处理
SMBv1 仍显示 True命令未以管理员身份运行用"以管理员身份运行"重开 PowerShell
Disable-WindowsOptionalFeature 提示需重启组件卸载要重启才完成做完全部任务、拍快照前统一重启
Set-Service 报"无法停止"有依赖服务仍在运行用 Get-Service 名称 -DependentServices 查看
Get-Service CertSvc 找不到在 SVR2 上运行了报告CA 在 DC1 上，报告在 DC1 运行
旧客户端连不上共享它只会 SMBv1 或 NTLMv1升级客户端，不要为它回退基线
最后一行是生产环境最常见的冲突：加固后某台老打印机或老系统连不上了。正确的做法是评估风险、升级或隔离那台设备，而不是把整个域的基线降回去。先自查，再把遇到的问题汇总记录。
