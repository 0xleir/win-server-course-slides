概念 1

四种工具，看不同的层次

工具回答的问题特点
netstat开了哪些端口？谁在连？系统自带，一次性快照
Get-NetTCPConnection端口属于哪个进程？输出是对象，可筛选排序
TCPView连接实时怎么变化？图形界面，新建/断开会变色
ProcMon哪个进程在收发网络数据？记录进程级 TCP/UDP 操作
Wireshark线上传的到底是什么内容？逐包解码，可看到载荷
一句话：前四个看"连接和进程"，Wireshark 看"数据包内容"。
把工具按"看得多深"排序：netstat 只看到连接表，Wireshark 能看到每个字节。提问：发现一个陌生的外连，先用哪个工具定位进程，再用哪个工具看内容？常见误区：以为 netstat 能看到流量内容，它只列连接状态。
概念 2

捕获过滤器 vs 显示过滤器

捕获过滤器（抓之前）

  • 开始捕获前设置，不符合的包直接丢弃
  • BPF 语法：host、port、tcp port
  • 例：host 10.10.10.100
  • 适合长时间抓包，节省磁盘

显示过滤器（抓之后）

  • 只是隐藏，包仍在文件里，可随时改
  • 字段语法：ip.addr、tcp.port
  • 例：ip.addr == 10.10.10.100
  • 课堂分析主要用这一种
易错：两种语法不通用。在捕获过滤器里写 ip.addr == ... 会报语法错误。
打个比方：捕获过滤器是"只录这个人的电话"，显示过滤器是"录了所有电话，回放时只听这个人"。捕获过滤器漏掉的包无法找回，所以课堂上建议不设捕获过滤器、全部抓下来再用显示过滤器。过滤栏变绿表示语法正确，变红表示错误。

明文协议（HTTP 等）

任务 1 · 22′ · DC1

命令行：端口 ↔ 进程

在 DC1 上，以管理员身份运行（netstat -b 需要管理员）

netstat -ano | findstr LISTENING
netstat -b   # 显示关联进程
netstat -s   # 协议统计


$name = @{N='ProcessName'
  E={(Get-Process -Id $_.OwningProcess).Name}}
Get-NetTCPConnection -State Listen |
  Select-Object LocalPort, OwningProcess, $name |
  Sort-Object LocalPort
-ano：a 全部连接、n 数字地址、o 显示 PID。最后一列 PID 可到任务管理器里对照。
自己操作，对照输出逐个说出端口对应的服务：53 DNS、80/443 IIS、88 Kerberos、389 LDAP、445 SMB。原文是一行写完的计算属性，这里把它放进变量 $name，效果完全相同。netstat -b 输出较慢且必须管理员运行，否则提示"请求的操作需要提升"。

任务 2 · 27′ · DC1 + CLIENT1

HTTP 明文 vs HTTPS 加密

① CLIENT1 访问 http://10.10.10.10

  • 过滤 http
  • 右键 HTTP 包 → 追踪 TCP 流
  • 📝 完整的请求头与网页内容可读

② CLIENT1 访问 https://www.lab.local

  • 过滤 tls
  • 只见 Client Hello、证书交换
  • 📝 Application Data 是密文
窃听者视角：如果网站登录页走 HTTP，账号密码就在 ① 的 TCP 流里。
这是本课的核心对比，自己讲解两个窗口的区别。HTTPS 站点是第 11 课在 IIS 上用自签名证书配置的，浏览器出现证书警告时选择继续即可。在 tls 过滤结果的 Client Hello 中展开 server_name，能看到 www.lab.local，说明 HTTPS 也会暴露访问的域名。如果 https 打不开，检查第 11 课的 443 绑定是否还在。
任务 3 · 18′ · CLIENT1 + DC1

抓取 DNS 与 SMB 流量

在 CLIENT1 上（Wireshark 保持捕获）

nslookup www.lab.local 10.10.10.10
net use Z: \\10.10.10.10\IT-Share /user:lab\alice "Domain@2026!"

过滤 dns

  • 一问一答：Query → Response
  • 响应里 A 记录 = 10.10.10.10

过滤 smb2

  • Negotiate → Session Setup（认证）
  • Tree Connect → 文件操作
DNS 走 UDP 53，明文，任何人都能看到你查询了什么域名。SMB 的 Session Setup 里是 NTLM 或 Kerberos 认证，看不到明文密码，但能看到用户名 alice，可以留意"用户名泄露"对后面第 28 课密码喷射的价值。如果 Z: 已被占用，先执行 net use Z: /delete 再映射。

排障

抓不到包？按这个顺序查

现象原因处理
接口列表为空Npcap 未安装或未启动重新运行 Wireshark 安装包，勾选 Npcap
抓到包但没有 HTTP选错网卡，或浏览器用了缓存换有 10.10.10.10 的网卡；Ctrl+F5 强制刷新
过滤栏变红语法错误或混用两种过滤器显示过滤器用 ==，字段名小写
netstat -b 被拒绝未以管理员运行以管理员身份打开 PowerShell
看不到 smb2Z: 已映射，连接被复用net use Z: /delete 后重新映射
最常见的是选错网卡：DC1 若有多块网卡，看接口列表右侧的流量曲线，跳动的才是正在用的。浏览器缓存会导致返回 304 甚至不发请求，所以强制刷新很重要。net use /delete 只断开映射，不会删除共享里的文件。
