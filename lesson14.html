概念

远程桌面：Windows 自带 vs 第三方工具

Windows 远程桌面服务

一种远程操作电脑的模式，可视化访问远程计算机的桌面环境；常用于管理员在客户机上对远程服务器进行管理。系统自带、无需额外安装，基于 RDP 协议。

TeamViewer

  • 最流行的第三方远程桌面之一
  • 灵活、支持无人值守、高级安全规则
  • 全平台：Win/Mac/Linux/移动端

Chrome 远程桌面

  • Google 基于 Chrome 的方案
  • 设置简单、完全免费
  • 仅满足基本需求，无文件传输/远程打印

VNC

  • 开源远程桌面方案
  • 协议免费、客户端选择多
  • 跨平台通用
教材补充：Windows 远程桌面连接是一种远程操作电脑的模式，可以可视化访问远程计算机的桌面环境，主要用于管理员在客户机上对远程服务器进行管理。除了系统自带的方案，还有常见的第三方工具：TeamViewer 是最受欢迎的产品之一，灵活性强，运行一次即可长期使用，支持无人值守和高级安全规则，覆盖 Windows、Mac、Linux、Chrome OS 以及 Android、iOS 等移动端；Chrome 远程桌面是 Google 推出的方案，设置非常简单且完全免费，但只能满足基本远程需求，不支持文件传输和远程打印这类高级功能；VNC 是开源方案，协议免费提供给任何人使用，很容易找到优秀的客户端。本课重点学系统自带的 RDS，第三方工具了解即可。

概念 1

RDP：把"屏幕"搬过网络

CLIENT1mstsc 客户端
→
TCP 3389默认端口
→
DC1TermService 服务
方向传输内容
服务器 → 客户端屏幕画面（压缩后的图形更新）
客户端 → 服务器键盘、鼠标输入，剪贴板、驱动器重定向
开关在哪：注册表 fDenyTSConnections = 0 表示允许连接（名字是"拒绝"，0 即不拒绝）。
强调程序都在服务器上运行，网络里只传画面和输入，所以带宽低也能用。fDenyTSConnections 是双重否定，学生容易设反，可以提问：值为 1 是什么意思？服务名 TermService 在任务 2 重启时会用到。
概念 2

NLA：先验明身份，再给桌面

不启用 NLA

  • 先建立完整会话，再显示登录界面
  • 任何人都能让服务器分配资源
  • 易被耗尽资源（DoS）和暴力破解
  • 未认证就暴露更多攻击面

启用 NLA

  • 客户端在连接时先提交凭据（CredSSP）
  • 认证通过后服务器才创建会话
  • 未认证者拿不到登录桌面
  • Win10 客户端默认支持
所以：任务 1 必须勾选"仅允许使用网络级别身份验证的远程桌面连接"。
NLA 全称 Network Level Authentication。类比：没有 NLA 是先请人进门再查证件，有 NLA 是在门口查证件。可补充：BlueKeep（CVE-2019-0708）等 RDP 漏洞在启用 NLA 时，攻击者需先有合法凭据才能利用。
概念 3

谁能连？从哪连？连多久？

第 1 层 · 网络：防火墙放行哪个端口（3389 / 3390），公网走 RD Gateway 443
第 2 层 · 认证：NLA + 用户必须在 Remote Desktop Users 组
第 3 层 · 会话：加密级别"高"、活动 2 小时、断开 30 分钟
注意：改端口只能挡住"扫默认端口"的自动化攻击，扫全端口仍能发现。它是辅助手段，不能替代 NLA 和强密码。
这页是今天所有配置的地图：任务 1 对应第 2 层，任务 2 对应第 1、3 层，任务 3 对应公网场景。提问：只改端口、不开 NLA，安全吗？引导学生理解"安全靠叠加"。
任务 1 · 20′ · DC1

启用远程桌面：两种方式

方式一 · GUI（勾选 NLA）
服务器管理器›本地服务器›远程桌面›启用
方式二 · PowerShell（管理员）

$ts = "HKLM:\System\CurrentControlSet\Control" +
      "\Terminal Server"
Set-ItemProperty -Path $ts `
  -Name "fDenyTSConnections" -Value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"
两步缺一不可：注册表打开服务，防火墙规则放行 3389，只做一步客户端仍然连不上。
任选一种方式，建议先用 GUI 看清 NLA 复选框，再用 PowerShell 理解背后改了什么。原文命令很长，这里用变量 $ts 保存路径，效果相同。中文系统里防火墙显示组名可能是"远程桌面"，若报找不到组，改用 -DisplayGroup "远程桌面"。

任务 2 · 24′ · DC1 → CLIENT1

把端口改为 3390

DC1 · 先放行新端口，再改注册表，最后重启服务

New-NetFirewallRule -DisplayName "Allow RDP 3390" `
  -Direction Inbound -Protocol TCP `
  -LocalPort 3390 -Action Allow
$k = "HKLM:\System\CurrentControlSet\Control" +
     "\Terminal Server\WinStations\RDP-Tcp"
Set-ItemProperty -Path $k -Name "PortNumber" -Value 3390
Restart-Service TermService -Force
CLIENT1 · 用新端口连接

mstsc /v:10.10.10.10:3390
这里把原文的顺序调整为先建防火墙规则再改端口，避免远程操作时把自己锁在外面（生产环境里这是血的教训）。Restart-Service 会断开当前所有 RDP 会话，所以必须在 DC1 控制台上操作改端口这一步。改完后切回 CLIENT1 窗口，再用不带端口的 mstsc 应该连不上，这正好证明改端口生效，然后用新端口重连验证。
任务 2 验证

端口真的改了吗？


Get-ItemProperty -Path $k -Name PortNumber
Get-NetTCPConnection -LocalPort 3390 -State Listen
Test-NetConnection 10.10.10.10 -Port 3390
命令（在哪运行）看到这个说明成功
Get-ItemProperty（DC1）PortNumber : 3390
Get-NetTCPConnection（DC1）有 LocalPort 3390、State Listen 的记录
Test-NetConnection（CLIENT1）TcpTestSucceeded : True
这三条是补充的只读检查命令，按"配置 → 监听 → 网络可达"三个层次排查。$k 是上一页定义的变量，如果新开了 PowerShell 窗口需要重新定义。Test-NetConnection 失败而前两条成功，说明问题在防火墙。

排障

连不上？按这个顺序查

现象原因处理
"无法连接到远程计算机"RDP 未启用或防火墙没放行查 fDenyTSConnections=0 和防火墙规则
"未授予远程登录权限"用户不在 RD Users 组charlie 属预期；alice 则检查 IT-Admins 是否已加入
改端口后连不上没写端口或 3390 未放行写 :3390，用 Test-NetConnection 测
用户名或密码不正确没写计算机名前缀写成 DC-01\alice
先分清是网络不通（前三秒就报错）还是认证被拒（输完密码才报错）。
遇到报错时先描述清楚发生在哪一步，再对照这张表排查。网络类错误用 Test-NetConnection 判断，认证类错误到 DC1 的事件查看器"安全"日志看 4625 事件。如果 Restart-Service 后服务没起来，可在 DC1 上 Get-Service TermService 查看状态。

本课小结

为什么

远程管理省去跑机房，但 RDP 是高价值攻击目标，必须加固

怎么做

启用 + 防火墙 → 授权 RD Users → 策略限制 → 改端口 3390

关键点

NLA 必开；改端口要先放行防火墙；公网走 RD Gateway
