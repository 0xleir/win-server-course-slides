概念 1

RDP vs PowerShell Remoting

远程桌面 RDP（上节课）

  • 传输整个桌面画面，占带宽
  • 一次只能操作一台服务器
  • 靠人工点鼠标，难以自动化
  • 端口 3389

PowerShell Remoting（本课）

  • 只传命令和结果对象，非常轻量
  • 一条命令同时发给多台服务器
  • 可写成脚本，天然适合自动化
  • 基于 WinRM，端口 5985 / 5986
一句话：RDP 适合"偶尔看一眼"，Remoting 适合"批量、重复地管"。
提问：Server Core（无桌面版）上没有图形界面，你怎么管理它？答案就是 PowerShell Remoting 和远程 MMC。补充：5985 是 HTTP，5986 是 HTTPS；HTTP 下 WinRM 默认也会对内容加密（Kerberos/NTLM 会话加密）。
概念 2

一条远程命令是怎么跑起来的

① CLIENT1Invoke-Command
→
② WS-Man 协议HTTP 5985
→
③ DC1 WinRM 服务监听器 Listener
→
④ 远端执行wsmprovhost 进程
→
⑤ 结果回传序列化对象
组件作用
WinRM 服务Windows 的远程管理服务，负责收发请求
Listener 监听器在 5985 端口等待连接，Enable-PSRemoting 自动创建
防火墙规则放行 5985 入站，同样由 Enable-PSRemoting 配好
Enable-PSRemoting 一条命令做了三件事：启动 WinRM 服务并设为自动、创建监听器、开防火墙规则。winrm quickconfig 是更老的等价命令。强调结果回来的是"序列化对象"，所以远程拿到的对象没有方法，只有属性。
概念 3

工作组里为什么要配 TrustedHosts

域环境（第 17 课以后）

  • 用 Kerberos 认证
  • 双方都能验证对方身份
  • 不需要 TrustedHosts

工作组环境（今天）

  • 只能用 NTLM，且用 IP 连接
  • 客户端无法验证服务器是不是"真的"
  • 默认拒绝 → 必须手动加入信任列表
注意：TrustedHosts 配在发起连接的一方（Client 配置），意思是"我愿意把凭据交给这些主机"。
这是本课最容易搞错的概念：TrustedHosts 不是"允许谁连我"，而是"我信任谁、愿意连它"。所以 CLIENT1 上必须把 10.10.10.10 加进去。课堂提问：把 TrustedHosts 设成 * 有什么风险？——凭据可能被发给冒充的服务器。
任务 1 · 20′ · DC1

在被管理端启用 WinRM

在 DC1 上，以管理员身份运行 PowerShell

Enable-PSRemoting -Force
winrm quickconfig

# 查看配置与监听器
winrm get winrm/config
Get-WSManInstance winrm/config/listener -Enumerate
监听器输出里应看到 Transport = HTTP、Port = 5985、Enabled = true。
winrm quickconfig 在已启用的情况下会提示"WinRM 服务已在此计算机上运行"，这是正常的，不是报错。winrm get 输出很长，让学生重点找 Service 下的 AllowUnencrypted = false 和 Auth 部分。
任务 1 · 20′ · DC1 + CLIENT1

配置 TrustedHosts

① DC1：信任整个实验网段


Set-Item WSMan:\localhost\Client\TrustedHosts `
  -Value "10.10.10.*" -Force

② CLIENT1：管理员 PowerShell


Enable-PSRemoting -Force
Set-Item WSMan:\localhost\Client\TrustedHosts `
  -Value "10.10.10.10" -Force


# 两台都可以这样确认
Get-Item WSMan:\localhost\Client\TrustedHosts
对比两种写法：DC1 用通配符信任整个网段（方便但范围大），CLIENT1 只信任 DC1 一个 IP（最小化原则）。注意 Set-Item 是覆盖而不是追加，如需追加要加 -Concatenate。Win10 上 Enable-PSRemoting 如果报"网络连接类型为公用"，见排障页。
任务 2 · 24′ · CLIENT1

交互式远程会话


$cred = Get-Credential   # 输入 DC-01\Administrator
Enter-PSSession -ComputerName 10.10.10.10 -Credential $cred

[10.10.10.10]: PS> hostname
[10.10.10.10]: PS> Get-Service W3SVC
[10.10.10.10]: PS> exit
提示符变了：前缀 [10.10.10.10]: 说明命令在 DC1 上执行
hostname 应返回 DC1，不是 CLIENT1；exit 回到本机
Get-Credential 弹框里用户名一定要写 DC-01\Administrator，只写 Administrator 会被当成 CLIENT1 的本地账号。W3SVC 是第 9–13 课装的 IIS 服务，应显示 Running。你可以在 DC1 上开另一个窗口观察任务管理器里的 wsmprovhost.exe 进程，验证远程会话确实建立了。
任务 2 · 24′ · CLIENT1

Invoke-Command：一次性远程执行

2.2 远程查看 CPU 占用前 5 的进程

Invoke-Command -ComputerName 10.10.10.10 -Credential $cred `
  -ScriptBlock {
    Get-Process | Sort-Object CPU -Descending |
      Select-Object -First 5
  }
2.3 多台并行（概念演示）· 2.4 远程运行本地脚本

Invoke-Command -ComputerName 10.10.10.10,10.10.10.100 `
  -Credential $cred -ScriptBlock { hostname }
Invoke-Command -ComputerName 10.10.10.10 -Credential $cred `
  -FilePath C:\LabFiles\remote-check.ps1
Enter-PSSession 像"打电话聊天"，Invoke-Command 像"发一条短信等回复"，后者才适合脚本化。结果里会多一列 PSComputerName，标明是哪台机器返回的。-FilePath 的脚本放在 CLIENT1 本地，由 PowerShell 读取后发到远端执行，DC1 上不需要有这个文件。
任务 2 验证

两种方式对比与预期结果

命令适用场景看到这个说明成功
Enter-PSSession临时登录一台机器排查提示符带 [10.10.10.10]:
-ScriptBlock批量执行一小段命令输出多一列 PSComputerName
多台 -ComputerName同时管多台服务器每台各返回一行主机名
-FilePath执行写好的检查脚本显示 remote-check.ps1 的检查输出
2.3 是概念演示：10.10.10.100 不在 CLIENT1 的 TrustedHosts 里，可能报错，只要 DC1 那一行成功即可。
多台并行时，一台失败不影响其他机器，错误会以红字单独显示，这正好展示了 Invoke-Command 的容错特性。可以让学生思考：如果想让 10.10.10.100 也成功，需要改哪台机器的什么配置？
任务 3 · 16′ · CLIENT1 / DC1

MMC 远程管理与服务器管理器

3.1 服务器管理器添加远程服务器（CLIENT1 需有 RSAT，否则在 DC1 上做）
服务器管理器›添加要管理的服务器›DNS›输入 IP 并添加
3.2 MMC 远程计算机管理
mmc›文件›添加/删除管理单元›计算机管理›另一台计算机：10.10.10.10
3.3 远程事件查看器
eventvwr.msc›右键"事件查看器(本地)"›连接到另一台计算机
MMC 走的不是 WinRM：计算机管理、事件查看器主要用 RPC/DCOM，需要防火墙放行对应规则。
工作组环境下 MMC 连远程常报"拒绝访问"，可以先在 CLIENT1 执行 cmdkey /add:10.10.10.10 /user:DC-01\Administrator /pass 保存凭据（会提示输入密码），或连接时选"以其他用户身份连接"。服务器管理器则使用 WinRM，可与任务 1 联系起来。如果 CLIENT1 没装 RSAT，也可以直接切到 DC1 本机上用服务器管理器操作，验证效果是一样的。
排障

远程连不上？按这个顺序查

现象原因处理
"WinRM 客户端无法处理该请求"TrustedHosts 没配在 CLIENT1 上加 10.10.10.10
Enable-PSRemoting 报"公用网络"Win10 网卡被识别为公用-SkipNetworkProfileCheck 或改为专用网络
拒绝访问账号没写机器前缀写成 DC-01\Administrator
连接超时5985 未放行 / 服务未启动Test-WSMan 10.10.10.10 检查
MMC 连接失败RPC 防火墙规则未开DC1 放行"远程事件日志管理"等规则
Test-WSMan 是最快的探测手段：返回协议版本信息就说明 WinRM 端口通、服务在跑，剩下就是认证问题。先让学生自己用 Test-WSMan 定位是"网络层"还是"认证层"问题，再对照此表。
