先像攻击者一样看自己的网络，再从日志里把他找出来

⏱ 80 分钟🧑 独立操作VM1 + VM4
开场提问：攻击者进入内网后做的第一件事是什么？答案几乎总是"侦察"：找活着的主机、开着的端口、跑着的服务。今天由你自己先切到 Kali 用 Nmap 扫描 DC1，记录活跃主机和服务清单；再切回 DC1 找扫描痕迹；最后自己汇总"发现-风险-加固建议"表——攻击方和防御方都是你一个人依次完成。必须强调：扫描只针对实验网 10.10.10.0/24，对未授权目标扫描违反《网络安全法》，可能承担法律责任。

概念 2

TCP 全连接 vs SYN 半连接 vs UDP

参数过程特点
-sT 全连接SYN → SYN/ACK → ACK，完成三次握手无需 root；最容易被目标日志记录
-sS 半连接SYN → SYN/ACK → RST，不完成握手需 root；速度快，应用层看不到连接
-sU UDP发 UDP 包，看是否回 ICMP 不可达很慢；DNS 53、SNMP 161 等靠它发现

open

回 SYN/ACK，有服务在监听

closed

回 RST，主机在但端口没开

filtered

没回应，被防火墙丢弃

可以联系第 26 课：在 DC1 的 Wireshark 里过滤 ip.addr==10.10.10.50，对比 -sT 和 -sS 的握手差异。半连接"隐蔽"只是对应用层而言，防火墙和 IDS 照样能看到。filtered 本身就是信息：说明有防火墙。
任务 1 · 27′ · Kali

主机发现与端口扫描

在 Kali 终端执行（-sS / -sU 需要 sudo）

nmap -sn 10.10.10.0/24              # 主机发现
nmap -sT 10.10.10.10                # TCP 全连接
sudo nmap -sS 10.10.10.10           # SYN 半连接
sudo nmap -sU 10.10.10.10 --top-ports 20
nmap -p 1-65535 10.10.10.10         # 全端口，可跳过
记录：-sn 发现了哪几台活跃主机？-sT 与 -sS 的结果一样吗？
自己操作，把活跃主机和开放端口抄到记录表。-sn 只做主机发现不扫端口，应能看到 .10、.20、.50 和 CLIENT1 的 DHCP 地址。原文 -sU 没写 sudo，但 UDP 扫描同样需要 root，否则报错。全端口扫描可放到最后，它能发现 3390 这样的非标准端口。
任务 1 · 27′ · Kali

服务版本与操作系统识别


nmap -sV 10.10.10.10       # 每个开放端口的服务和版本
sudo nmap -O 10.10.10.10   # 操作系统检测

-sV 看什么

  • SERVICE 列：服务名
  • VERSION 列：产品与版本号
  • 3390 → ms-wbt-server（RDP）

-O 看什么

  • OS details：Windows Server 2016/2019/2022
  • 结果是"猜测"，带准确率
版本号是漏洞匹配的依据：知道版本就能查对应 CVE。-O 需要至少一个 open 和一个 closed 端口才准确，防火墙丢包太多时会显示"too many fingerprints"。提问：如何让 -sV 拿不到准确版本？引出关闭 Banner、最小化服务。
检测与防御 · 任务 1

如何发现和限制端口扫描

检测

  • 防火墙日志：同一源 IP 短时间访问大量端口
  • 大量 DROP 记录 = 典型扫描特征
  • 任务 3 现场验证

防御

  • 只开放业务需要的端口
  • 管理端口（RDP/WinRM）限定来源 IP
  • 禁止 ICMP 回显可降低 -sn 命中率
注意：扫描无法完全阻止，目标是"减少暴露面 + 尽早发现"。
记下这些要点，任务 3 用日志验证。限定 RDP 来源可以回顾第 21 课的 -RemoteAddress 参数。思考：如果 ICMP 被禁止，-sn 还能发现主机吗？在同网段 Nmap 会用 ARP 探测，所以仍然能发现。
任务 2 · 22′ · Kali

Nmap 脚本引擎 NSE


T=10.10.10.10
nmap --script vuln $T              # 漏洞扫描
nmap --script smb-enum-shares $T   # SMB 共享
nmap --script http-enum $T         # Web 目录
nmap --script dns-brute $T         # DNS 爆破
nmap --script rdp-enum-encryption $T -p 3390
记录：vuln 报告的潜在漏洞（VULNERABLE 字样）和枚举到的共享名、目录名。
用变量 T 只是为了缩短行，效果和原文逐条写 IP 一样。vuln 类脚本较慢，先跑 vuln，同时记录其他脚本输出。rdp-enum-encryption 必须带 -p 3390，因为 RDP 已不在默认 3389。提醒：NSE 里还有 dos、brute 类脚本，未经授权不得使用。
任务 2 · 22′ · Kali

输出扫描报告


nmap -sV --script vuln -oA /home/vagrant/scan-dc1 10.10.10.10
ls /home/vagrant/scan-dc1.*
文件格式用途
scan-dc1.nmap普通文本人读，写报告
scan-dc1.xmlXML导入其他工具分析
scan-dc1.gnmapgrep 友好一行一主机，便于筛选
-oA 一次生成三种格式。根据 .nmap 文件整理"端口-服务-风险-加固建议"表，作为本课的核心产出。扫描报告本身属于敏感信息，不要上传到公网或群聊。
检测与防御 · 任务 2

针对漏洞扫描与服务枚举

攻击方发现防御方对策
vuln 报出 SMB 漏洞及时打补丁；禁用 SMBv1
smb-enum-shares 列出共享收紧共享与 NTFS 权限（第 6–7 课）
http-enum 找到目录删除默认页面、关闭目录浏览
dns-brute 得到子域名禁止区域传送到任意服务器
RDP 加密等级低要求 NLA 与 TLS（第 14 课）
把这张表填进报告，每一项写上"是否在本环境发现"。强调漏洞扫描结果有误报，要人工确认。这些加固项本课只讨论，不在本课修改，以免影响后续课程的快照。
任务 3 · 18′ · DC1

在 DC1 上找扫描痕迹


$log = "C:\Windows\System32\LogFiles\Firewall\pfirewall.log"
Get-Content $log -Tail 50 |
    Where-Object { $_ -match "10.10.10.50" }

Get-WinEvent -LogName Security -MaxEvents 50 |
    Where-Object { $_.Message -match "10.10.10.50" } |
    Format-Table TimeCreated, Id, Message -Wrap
📝 讨论：如何从防御角度识别和阻止扫描行为？
以管理员身份运行，读 pfirewall.log 需要管理员权限。只取最后 50 行，如果扫描已经过去较久可加大 -Tail。安全日志里不一定有 10.10.10.50：默认审核策略不记录被丢弃的连接，只有触发登录尝试时才有 4625 等事件。讨论时可以结合自己刚才扮演攻击方时的操作，想一条防御办法。
预期结果

日志里应该看到什么

来源典型内容说明
pfirewall.logDROP TCP 10.10.10.50 10.10.10.10 大量不同目标端口被拦截的探测
pfirewall.logALLOW TCP ... 445 / 3390放行端口，就是扫描发现的 open
Security4624 / 4625，含 10.10.10.50NSE 脚本尝试登录 SMB 时产生
Security 为空没有匹配结果正常：纯端口扫描不产生登录事件
只有日志开着才能"看见"攻击，这是第 21 课开启日志的意义。
数一数 10.10.10.50 的 DROP 记录有多少条、涉及多少个不同端口，这就是识别扫描的思路。4625 表示登录失败，下节课的密码攻击会大量产生。如果 pfirewall.log 一条都没有，回看排障表。
