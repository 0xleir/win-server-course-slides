概念

IIS 状态码与日志

状态码含义
200成功，IIS 已成功处理请求
304未修改，文档已在缓存中且未变动
401.1登录失败，用户名或密码无效

IIS 日志的作用

  • 记录每次请求的状态码
  • 记录访问者的 IP 来源
  • 服务器的运行状况可据此追查
  • 是管理员排障与安全分析的依据
要点：客户端通过 HTTP/FTP 访问时，IIS 用数字状态码表明请求是否成功及失败原因，并写进日志。
这页补充教材必备知识，和今天的安全加固直接相关。先讲状态码：当用户用 HTTP 或 FTP 访问 IIS 服务器时，IIS 会返回一个数字代码表示这次请求的状态，这个代码既会写进日志，也可能显示在浏览器里。状态码能告诉我们请求是否成功，失败时还能看出原因——比如 200 表示成功，IIS 已经正确处理了请求；304 表示未修改，说明浏览器请求的文档已经在它自己的缓存里，而且自上次缓存以来没变过，所以不用重新下载；401.1 表示登录失败，通常是用户名或密码错误。再讲日志：IIS 日志是每个服务器管理员都必须学会看的，服务器的运行状况、谁访问过、访问者的 IP 来源都记录在里面，所以查日志是排障和安全分析最基本的手段。后面任务里收紧访问之后，就要靠日志验证到底是谁被拦了。

概念 1

HTTP vs HTTPS

HTTP（明文）

  • 内容、表单、Cookie 全部明文传输
  • 同网段抓包就能看到账号密码
  • 无法确认对方真是 www.lab.local
  • 默认端口 80

HTTPS（HTTP + TLS）

  • 传输内容加密，抓包只看到乱码
  • 证书证明服务器身份
  • 内容被篡改会被发现
  • 默认端口 443
一句话：证书 = 服务器的"身份证"，里面带着公钥，用来建立加密通道。
可以提问：HRPortal 上如果有员工工资信息，用 http 有什么风险？强调 HTTPS 提供三件事：机密性、身份认证、完整性。抓包演示放到后面 Kali 的课程，这里口头说明即可。
概念 2

为什么浏览器会警告自签名证书？

① 浏览器连接https://www.lab.local
→
② 服务器出示证书DnsName = www.lab.local
→
③ 检查签发者是受信任的 CA 吗？
→
④ 建立加密协商会话密钥
检查项自签名证书的结果
域名是否匹配✓ 证书含 www.lab.local、hr.lab.local
是否在有效期内✓ NotAfter = 两年后
签发者是否可信✗ 自己给自己签发，客户端不信任 → 警告
自签名证书加密强度和正规证书一样，问题只在"没人担保"。第 3 步失败才会出现警告，所以实验里点"继续"是可以的，但生产环境绝不能教用户习惯点继续。后面学 AD 证书服务（ADCS）时，会用企业 CA 签发证书，客户端就不再警告。
概念 3

一个请求要过几道关？

客户端请求来自某个 IP
→
IP 地址限制不在允许网段 → 403
→
请求过滤.bak / bin 等 → 404
→
返回页面站点内容

IP 地址限制

管"谁能来"：HRPortal 是内部站点，只允许 10.10.10.0/24

请求过滤

管"什么能看"：备份文件、配置文件、程序目录不该被下载

这就是"纵深防御"：每一层都只管一件事，任何一层挡住都行。提问：如果开发人员把数据库备份 site.sql 放在网站根目录，没有请求过滤会怎样？请求过滤故意返回 404 而不是 403，是为了不暴露"这个文件其实存在"。
任务 1 · 20′ · DC1

创建自签名 SSL 证书

在 DC1 上，以管理员身份运行 PowerShell

New-SelfSignedCertificate `
  -DnsName "www.lab.local","hr.lab.local" `
  -CertStoreLocation cert:\LocalMachine\My `
  -FriendlyName "Lab SSL Cert" `
  -NotAfter (Get-Date).AddYears(2)


Get-ChildItem cert:\LocalMachine\My |
  Format-Table Thumbprint, Subject, NotAfter
-DnsName 写了两个名字：一张证书同时覆盖 www 和 hr 两个站点；FriendlyName 是稍后在 IIS 下拉框里看到的名字。
证书必须放在 LocalMachine\My（计算机的"个人"存储），IIS 只从这里找证书，放到 CurrentUser 下 IIS 是看不到的。Get-ChildItem 输出里 Subject 应为 CN=www.lab.local，记下 Thumbprint，排障时会用到。常见错误：反引号后面多了空格。

任务 2 · 12′ · DC1

HTTP 重定向到 HTTPS

建一个只负责跳转的小站点 WWW-Redirect，把 http:80:www.lab.local 从 CompanySite 移给它：

CompanySite › 绑定›删除 http 80 www.lab.local›添加网站 WWW-Redirect›HTTP 重定向

WWW-Redirect

路径 C:\WebSites\Redirect
http · 80 · www.lab.local

HTTP 重定向

勾选「将请求重定向到此目标」
https://www.lab.local

状态代码

永久 (301)
别在 CompanySite 上直接开！它同时有 http 和 https 绑定，重定向对 https 也生效 → https 跳 https，浏览器报"重定向次数过多"（真机实测）。
原手册是在 CompanySite 上直接开 HTTP 重定向（或写 web.config），真机实测会形成循环：https://www.lab.local 也返回 301 跳到自己。IIS 自带的 HTTP 重定向不能按协议区分，所以把 http 绑定交给一个专门跳转的站点，CompanySite 只留 https，这样每个站点只干一件事。另外，"HTTP 重定向"图标默认不随 IIS 安装，需要先装 Web-Http-Redirect 角色服务。用 URL 重写模块按"HTTPS=off"跳转是生产中常见的做法，但它要另外下载安装。301 会被浏览器缓存，测试用无痕窗口。
任务 3 · 20′ · DC1

HRPortal：只允许内网访问

IIS 管理器›HRPortal›IP 地址和域限制

① 添加允许条目

  • IP 地址范围：10.10.10.0
  • 掩码：255.255.255.0（即 /24 内网）

② 编辑功能设置

  • 未指定的客户端的访问权：拒绝
  • 效果：不在白名单里的 IP → 403
找不到这个图标？需先安装角色服务：Install-WindowsFeature Web-IP-Security，然后重开 IIS 管理器。
关键是第 ② 步：只加允许条目而不把默认改成"拒绝"，等于什么都没限制。这是"白名单"思路：默认拒绝、按需放行。"IP 地址和域限制"默认不随 IIS 安装（第 9 课我们已经用 Web-IP-Security 装过，图标应该直接在），安装角色服务不需要重启。
任务 3 · 20′ · DC1

CompanySite：请求过滤

IIS 管理器›CompanySite›请求筛选

「文件扩展名」选项卡

拒绝文件扩展名：

.bak.config.sql

「隐藏段」选项卡

添加隐藏段：

binApp_Data

扩展名按文件后缀拦截；隐藏段按 URL 中的目录名拦截，例如 /bin/任何文件 都访问不到。
中文界面里叫"请求筛选"，原文写作"请求过滤"，是同一功能。添加 .config 或 bin 时如果提示"已存在"，说明 IIS 默认已经拦截了，这是正常的，正好说明微软默认就认为这些很危险。请求过滤命中时返回 404，日志里的子状态码可以区分：404.7 是扩展名被拒，404.8 是隐藏段。

排障

常见故障

现象原因处理
绑定时下拉框里没有证书证书没放在 LocalMachine\My按原命令重新创建，Get-ChildItem 确认
https 打不开 / 连接超时防火墙未放行 443启用"万维网服务(HTTPS 流量)"入站规则
"重定向次数过多"HTTP 重定向开在了 CompanySite 上，https 也被跳转关掉 CompanySite 的重定向，改由 WWW-Redirect 跳转；无痕窗口测试
HRPortal 内网也 403允许条目掩码写错检查 10.10.10.0 / 255.255.255.0
test.bak 仍能下载规则加到了别的站点确认在 CompanySite 上配置请求筛选
重定向循环说明：HTTP 重定向写在站点级 web.config 里，对 https:443 绑定的请求同样生效，访问 https 也会被再次跳转，所以访问 https 也会跳到自己，形成循环。处理办法：改用 URL 重写模块按"HTTPS 为 off"条件跳转，或在 SSL 设置里勾选"要求 SSL"代替跳转。301 会被浏览器缓存，修好配置后一定换无痕窗口测试。

本课小结

为什么

明文 HTTP 可被窃听；内部站点和敏感文件不应对所有人开放

怎么做

证书 → https 绑定 → 301 跳转 → IP 白名单 → 请求筛选

关键点

默认拒绝、按需放行；自签名证书能加密但不被信任
